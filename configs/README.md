# `configs/` — конфигурация домена

> **Назначение:** Каталог, нормы, реестр моделей, сроки и примеры локальной конфигурации.
> **Владелец:** по файлам · **Статус:** действующие файлы и планируемые настройки перечислены отдельно.

## Доступные файлы

| Файл | Что делает |
|---|---|
| `catalog/<CODE>.yaml` | [S0 v0 → владелец кода] запись каталога на каждый код нарушения |
| `catalog/signals.yaml` | [S0] 13 кодов `SIG_*` |
| `legal/acts.yaml` | [S0] акты РК |
| `deadlines.yaml` | [S1] сроки от t0: vision_target +150 с, vlm_start_cutoff +180 с, vlm_stop +210 с, finalize_at +225 с |
| `models.yaml` | [S0, правит S3] роль → версия, путь, sha256, imgsz, бэкенд по платформе, ревизия и квант VLM |
| `trackers/botsort_static.yaml` | [S3] трекер |
| `local_analysis.temporal.example.json` | [S1] локальные веса, SHA-256 и временные правила PT-профиля |
| `local_analysis.mac.example.json` | [S1] пример CPU PT-конфигурации; текущая версия на Mac не проверена |

Реальный набор включённых правил и их параметры задаются в локальном JSON через
`CG_LOCAL_ANALYSIS_CONFIG`; актуальный пример — в [главном README](../README.md#полный-анализ-с-локальными-моделями).

## Планируемые настройки

`rules/<CODE>.yaml` (владелец кода), `scene.yaml` (S4), `perception.yaml` (S3),
`vlm.yaml` (S6) и `perf_budget.yaml` (S1) пока не поставлены. Папки создаются вместе
с реализацией. Будущие пороги подбираются по LOSO L1–L5 с целью recall по видео 1.0;
изменения правил требуют сравнения с проверенной baseline. Методика и текущий
статус команд — в [docs/eval.md](../docs/eval.md).

## Правила

- `config_hash` = sha256 нормализованного YAML; хранится в каждой задаче и входит в ключ кэша результатов.
- Секреты и переключатели режимов — не здесь, а в переменных `CG_*`.
