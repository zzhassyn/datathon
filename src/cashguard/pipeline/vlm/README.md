# `src/cashguard/pipeline/vlm/` — проверка VLM

> **Назначение:** Вопросы к Qwen3.5-4B по кандидатам и проход по ключевым кадрам (ADR-0010).
> **Владелец:** S6 · **Статус:** черновик v1, 17.10.2026 (каркас: кода ещё нет)

## Планируемые файлы

| Файл | Что делает |
|---|---|
| `questions.py` | `vlm.plan_questions(decisions, store, cfg) -> list[VlmQuestion]`: 4–8 кадров ~0,75× + мозаика увеличенных фрагментов, таймстемпы в тексте |
| `grouping.py` | группы кандидатов с якорями в пределах ±2 с, порядок по `\|score − τ\|` |
| `schema.py` | JSON-схемы ответов для llguidance, собираются один раз при старте |
| `keyframes.py` | проход по 12–16 ключевым кадрам в половинном разрешении → `KeyframeFinding`; по умолчанию это сигналы |
| `quant.py` | `CG_VLM_QUANT=auto`: после прогрева 8-bit, если свободно < 3,0 ГБ — 6-bit, затем 4-bit |
| `prompts/` | шаблоны промптов YAML |
| `backends/` | реализации `VlmBackend` |

## Правила

- Thinking выключен, temperature 0, `max_tokens` 96 (160 для прохода по кадрам), ответ по JSON-схеме.
- Срок `vlm_stop` проверяется на каждой порции потока; если не успели — уходит результат по правилам.
- `OTHER_VISIBLE_IRREGULARITY` влияет на вердикт только при подтверждении треками и выше высокого τ (политика уточняется).
- `VlmAnswer.note` — только для UI и отладки, никогда в описании для жюри.
- Модели только локальные, `HF_HUB_OFFLINE=1`. Параметры — `configs/vlm.yaml`.
