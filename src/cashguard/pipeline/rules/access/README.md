# `src/cashguard/pipeline/rules/access/` — доступ в кассу

> **Назначение:** Правила про дверь и людей, которые входят в кассовое помещение.
> **Владелец:** S4 · **Статус:** числовой вариант `THIRD_PERSON_DURING_SERVICE` реализован; обновлено 09.11.2026

## Файлы и план

| Файл | Что делает |
|---|---|
| `door_not_closed.py` | `DOOR_NOT_CLOSED`: после входа дверь `open` ≥ N с, у двери никого; таймкод — вход + N |
| `outsider_in_cash_room.py` | `OUTSIDER_IN_CASH_ROOM`: новый трек с ролью `outsider`; таймкод — появление |
| `third_person_during_service.py` | Реализован: `THIRD_PERSON_DURING_SERVICE`, два посетителя одновременно у рабочего места; таймкод — начало устойчивого интервала |
| `storage_unescorted.py` | `STORAGE_UNESCORTED`: вход в зону хранения без сопровождения (пункт 39 списка команды) |

## Правила

- Каждый файл — класс с `@register_rule`, протокол `Rule`: `code`, `version`, `verdict_impact`, `evaluate(ctx) -> list[Candidate]`.
- Тест `tests/unit/rules/<CODE>_test.py`, фикстуры `tests/fixtures/timelines/<CODE>_{pos,neg}_*.json`.
- Кандидат не должен срабатывать на 19 чистых роликах (`uv run just eval-replay`).
- Только Python + numpy: модуль работает в режиме replay на Windows без моделей и Mac.

## Реализованный числовой вариант

`third_person_during_service.evaluate_frames` проверяет устойчивое одновременное
присутствие двух посетителей у рабочего места, исключая кассира, дубли рамок
и наблюдения вне заданных зон. Начало сеанса сохраняется при открытии интервала:
новый сеанс после разрыва наблюдений не меняет факты уже завершённого события.
Короткие интервалы через разрыв не объединяются. Регрессионные тесты на
синтетических числовых наблюдениях —
`tests/unit/rules/THIRD_PERSON_DURING_SERVICE_test.py`.

Дубли одного ID считаются одним человеком. Перекрывающиеся рамки подавляются
по уверенности после проверки размера, независимо от порядка детекций. Фильтр
обрезанного человека у двери работает у обоих горизонтальных краёв кадра.

По умолчанию `person_size_mode="adaptive"` оценивает минимальную высоту по медианам устойчивых треков
посетителей. На каждом PTS голосуют только наблюдаемые там устойчивые участки
треков, по одному голосу на ID независимо от длительности. Поздние люди и
повторно использованные ID после разрыва не меняют ранний порог.
При недостатке уверенных наблюдений используется прежний порог площади;
`person_size_mode="fixed"` позволяет явно выбрать его для всех наблюдений.
Ослабление порога
площади разрешено только внутри подтверждённого непрерывного участка трека;
будущие наблюдения после разрыва не подтверждают ранний участок.
Пороги являются оценкой, точность на реальных видео не измерена. Конфигурация
и условия проверки описаны в `docs/pipeline.md`.

Для масштаба действует NMS; временная поддержка ID сохраняется отдельно до
подавления рамок разных ID. Неподходящий двойник не лишает подходящий трек
поддержки, при этом финальный подсчёт людей по-прежнему подавляет дубли.
Без `cashier_seat` рамка выбранного кассира вычисляется по его наблюдениям
в `cashier_roi`; широкая зона не используется как рамка человека.

`ThirdPersonDuringServiceRule` зарегистрирован для общего runner/replay:
адаптирует `PerceptionTrace`, требует однозначного кассира и прямоугольные
зоны `desk`/`cashier_side` (необязательную `door`). Неизвестные зоны или роли
дают ошибку. Версия — `numeric-auto-zones-v4`.
