Статус: черновик v1, 17.10.2026.

Связанные документы: [web/AGENTS.md](../web/AGENTS.md) — правила для агентов в `web/`; [architecture.md](architecture.md); [api.md](api.md); [legal_sources.md](legal_sources.md); `docs/violation_types.md` (генерируется `scripts/render_docs.py`, появится в P3); [limitations.md](limitations.md); [jury_mode.md](jury_mode.md); [ADR](adr/) 0007 (опрос вместо SSE), 0008 (отдельный `/api/ui`), 0014 (стек фронтенда). ## 1. Что требует ТЗ

Обязательный сценарий (ТЗ, раздел 4) и где он закрыт в UI:

| Один или несколько кадров-доказательств | Кадры и лайтбокс, [§5.8](#58-кадры-доказательства-evidencestrip-evidencelightbox) |
| Что видно и почему это может указывать на нарушение | Блок «Что видно» в карточке |
| Правило и нормативный источник: документ, пункт | Блок «Правило и источник», [§5.7](#57-правило-и-источник-legalreference); экран «Типы нарушений и нормы», [§6](#6-экран-типы-нарушений-и-нормы-typespage) |

Что ещё влияет на UI:
- Критерий 6 «Готовность продукта» (10 баллов): удобство интерфейса, надёжность загрузки и обработки, понятность результата.
- Критерии 2 и 4 жюри видит глазами в UI: таймкод с кадром и ссылка на норму.
- ТЗ, раздел 7: результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение.
- FAQ 26: язык на выбор команды. Выбран русский.
- FAQ 27: авторизация, история проверок, экспорт отчёта и пакетная загрузка не нужны.
- FAQ 29: распознавать и идентифицировать лица запрещено.
- FAQ 1: звука в видео нет.

UI и API жюри разделены. Жюри оценивает ответы автоматически через `/api/v1` (FAQ 18), но может загружать видео и через UI (FAQ 13: «удалённо, по ссылке команды»); лимиты UI в окне жюри ослаблены (раздел 4.3). UI работает только с `/api/ui/*` и `/ready`. Обе ветки вызывают один сервис анализа, поэтому UI показывает тот же результат, что ушёл бы в API жюри, плюс наблюдения и технические детали.

## 2. Пользователи

| Кто | Задача | Устройство | Что важно |
|---|---|---|---|
| Проверяющий банка | Загрузить новое видео, найти момент, проверить вывод по кадру и норме | Ноутбук или десктоп: Chrome, Edge, Safari | Быстро увидеть вердикт. Одним кликом перейти к моменту в видео. Увеличить кадр. Прочитать текст нормы |

## 3. Экраны и состояние в URL

Роутера нет. Экран выбирается по query-строке. `App.tsx` разбирает URL при загрузке и на событие `popstate`.

| URL | Экран | Файл |
|---|---|---|
| `/` | Загрузка + недавние проверки | `src/pages/UploadPage.tsx` |
| `/?job=<id>` | Проверка: статус и результат | `src/pages/JobPage.tsx` |
| `/?view=types` | Типы нарушений и нормы | `src/pages/TypesPage.tsx` |
| `/?view=types#<CODE>` | То же, с прокруткой к типу | `src/pages/TypesPage.tsx` |

Правила:
- Приоритет: есть `job` — JobPage. Иначе `view=types` — TypesPage. Иначе — UploadPage. Прочие параметры игнорируются.
- `job` проверяется регулярным выражением `^[0-9a-f]{32}$` до запроса. Не совпало — состояние «Неверная ссылка», запрос не отправляется.
- Переходы: `history.pushState` и перерисовка. «Назад» и «Вперёд» работают через `popstate`.
- Все переходы — настоящие ссылки `<a href>`. Клик перехватывается для SPA-перехода, кроме кликов с модификаторами (Ctrl, Cmd, Shift, средняя кнопка): они открывают новую вкладку штатно.
- В URL нет ничего, кроме `job` и `view`: ни имени файла, ни таймкода, ни персональных данных.
- Fallback для SPA на сервере не нужен: все экраны живут на `/`.
- При смене экрана: прокрутка наверх, фокус на `<h1>`, обновление `document.title`.
- Логика разбора и записи URL — в `src/shared/lib/urlState.ts`.

`document.title`:

| Экран и состояние | Заголовок вкладки |
|---|---|
| Загрузка | `CashGuard — загрузка видео` |
| Проверка, идёт анализ | `Анализ… — CashGuard` |
| Проверка, готово | `Готово — CashGuard` |
| Проверка, ошибка | `Ошибка анализа — CashGuard` |
| Типы и нормы | `Типы нарушений и нормы — CashGuard` |

### Общий каркас

- **Шапка:** название «CashGuard», подзаголовок «Проверка кассовой дисциплины по видео», ссылки «Новая проверка» и «Типы нарушений и нормы».
- **Основная область:** текущий экран.
- **Подвал:** индикатор готовности ([§7.2](#72-индикатор-готовности-readydot)), дисклеймер «подсказка для проверки человеком», строка о локальной обработке, срок хранения, версия сервиса.

## 4. Экран «Загрузка» (UploadPage)

### 4.1 Состав

1. Заголовок «Загрузите видео для проверки» и подсказка о формате.
2. Зона загрузки `UploadDropzone`: drag&drop плюс кнопка «Выбрать файл» (скрытый `<input type="file">`).
3. Во время загрузки зона заменяется карточкой прогресса: имя файла, размер, полоса прогресса, проценты, МБ из МБ, скорость, оставшееся время, кнопка «Отменить загрузку», локальный предпросмотр.
4. Предупреждение, если `/ready` не готов ([§7.2](#72-индикатор-готовности-readydot)). Загрузку не блокирует.
5. Список «Недавние проверки» ([§7.1](#71-недавние-проверки-recentjobs)).

### 4.2 Поток

1. Пользователь бросает файл в зону или выбирает его. Принимается ровно один файл. Несколько файлов — ошибка «Загрузите один файл за раз».
2. Проверка на клиенте (`validateFile.ts`):
   - расширение `.mov` или `.mp4` без учёта регистра;
   - размер больше 0;
   - размер не больше 100 МБ (`CG_MAX_UPLOAD_MB` = 100 и лимит тела запроса Cloudflare 100 МБ). Клиент считает 1 МБ = 1 000 000 байт: так проверка не мягче серверной. Единицу на сервере — проверить у S1.
   - MIME-тип не проверяем: браузеры передают его по-разному. Содержимое проверяет сервер (сигнатура ISO-BMFF, ответ 415).
3. Загрузка стартует сразу, без второй кнопки. `uploadVideo(file, onProgress, signal)` отправляет XHR `POST /api/ui/jobs`, multipart-поле `file`. `fetch()` не даёт событий прогресса отправки, поэтому только XHR.
4. Прогресс: проценты, «12,4 из 29,1 МБ», скорость МБ/с (сглаженная), оставшееся время. Загрузка 29 МБ — самая долгая часть ожидания: около 46 с при 5 Мбит/с (оценка из исследования фронтенда).
5. Отправлено 100 %, ответа ещё нет: «Файл загружен, сохраняем на сервере…». Сервер в это время делает fsync и запись в базу; бюджет — до 0,5 с после последнего байта.
6. Ответ 200 `{"job_id"}`:
   - запись в недавние проверки;
   - object URL локального предпросмотра кладётся в память вкладки под ключом `job_id`;
   - `pushState('/?job=<id>')` — сразу экран «Проверка», без лишнего клика.
7. Ошибка — текст из [§4.3](#43-ошибки-загрузки) под зоной загрузки и кнопка «Повторить» там, где повтор имеет смысл.

Защиты:
- Во время загрузки висит обработчик `beforeunload`. Браузеры показывают свой текст, а не наш.
- Повторная отправка заблокирована: зона неактивна, пока идёт загрузка.
- «Отменить загрузку» вызывает `xhr.abort()`.

Локальный предпросмотр:
- `URL.createObjectURL(file)` в `<video muted playsInline controls preload="metadata">`.
- Событие `error` (например, Chrome не играет этот .mov) — предпросмотр молча скрывается.
- Object URL освобождается (`URL.revokeObjectURL`) при новой загрузке или когда JobPage для этого задания размонтирован.

### 4.3 Ошибки загрузки

| Ситуация | Код | Текст (ключ `ru.ts`) | Действие |
|---|---|---|---|
| Не .mov и не .mp4 | клиент | «Нужен файл .mov или .mp4.» (`upload.error.wrongType`) | Выбрать другой файл |
| Пустой файл | клиент | «Файл пустой.» (`upload.error.empty`) | Выбрать другой файл |
| Больше 100 МБ | клиент или 413 | «Файл больше 100 МБ. Обрежьте или сожмите видео.» (`upload.error.tooLarge`) | Выбрать другой файл |
| Несколько файлов | клиент | «Загрузите один файл за раз.» (`upload.error.multiple`) | — |
| Содержимое не видео | 415 | «Файл не распознан как видео .mov или .mp4 либо повреждён.» (`upload.error.unsupported`) | Выбрать другой файл |
| Нет поля `file` | 422 | «Файл не дошёл до сервера. Выберите его ещё раз.» (`upload.error.noFile`) | Повторить |
| Лимит загрузок | 429 + `Retry-After` | «Сейчас слишком много проверок. Повторите через {время}.» (`upload.error.rateLimited`) | Кнопка «Повторить» неактивна до конца отсчёта |
| Нет места на сервере | 507 | «На сервере не хватает места. Попробуйте позже.» (`upload.error.noDisk`) | Повторить позже |
| Нужен код доступа | 401 | Экран кода доступа, [§7.3](#73-код-доступа-keygate) | — |
| Сбой сервера | 5xx, 502, 524 | «Сервер не смог принять файл. Повторите попытку.» (`upload.error.server`) | Повторить |
| Обрыв сети | `onerror` XHR | «Нет связи с сервером. Проверьте интернет и повторите.» (`upload.error.network`) | Повторить |
| Отмена пользователем | `abort` | «Загрузка отменена.» (`upload.cancelled`) | — |

Лимиты UI на сервере ([api.md](api.md), раздел 6.1), два профиля:
- обычный: 5 загрузок за 10 минут с одного IP, 2 активных задания на IP, общая очередь UI — 10 заданий;
- «окно жюри» (от заморозки до конца окна жюри): 30 загрузок за 10 минут с IP, 5 активных на IP, общая очередь UI — 20. Так член жюри может загрузить третий ролик, пока первые два ещё считаются, а несколько членов жюри за одним NAT площадки не упираются в 429.

Сверх лимита — 429 с `Retry-After`. Ключ жюри этими лимитами не ограничен. Задачи из UI идут по тем же рубежам дедлайнов от t0, что и задачи API ([api.md](api.md), раздел 3.7).

### 4.4 Чего на экране нет

Пакетной загрузки, настроек анализа, выбора модели, серверной истории, авторизации по умолчанию.

## 5. Экран «Проверка» (JobPage)

### 5.1 Порядок блоков

Телефон и узкий экран, сверху вниз:
1. Строка заголовка: «Проверка видео», имя файла (только если оно есть в локальном списке недавних), «Загружено 17.10.2026, 14:05», короткий номер (первые 8 символов `job_id`), кнопка «Скопировать ссылку».
2. Баннер: вердикт, предварительный результат или ошибка.
3. Шаги анализа — пока задание не завершено. После завершения — одна строка «Анализ занял 0:28» с раскрытием времени этапов.
4. Видео и шкала событий.
5. Карточки нарушений.
6. Аккордеон «Наблюдения (не влияют на вердикт)».
7. «Технические детали», свёрнуто.

Десктоп от `lg`: сетка `minmax(0,1fr) 420px`. Слева — блоки 1–3 и 5–7. Справа — видео со шкалой, колонка прилипает к верху (`position: sticky`).

### 5.2 Состояния

| Состояние | Условие | Что показываем |
|---|---|---|
| Загрузка данных | Первый запрос, кэша нет | Скелетоны баннера, шагов, плеера, двух карточек |
| Неверная ссылка | `job` не проходит `^[0-9a-f]{32}$` | «Неверная ссылка на проверку.» + «Загрузить видео» |
| Не найдено | 404 | `job.notFound` (срок хранения подставляется из настроек, раздел 12) + «Загрузить видео» |
| В очереди | `status = queued` | Баннер «Идёт анализ», позиция в очереди, шаги |
| Анализ | `status = running`, `provisional = false` | Баннер «Идёт анализ», шаги, прогресс текущего шага |
| Предварительный результат | `status = running`, `provisional = true` | Баннер «Предварительный результат», карточки с бейджем «Предварительно», шаги |
| Предварительный результат, ждёт VLM | `status = queued`, `provisional = true` | Как «Предварительный результат»; шаг `vlm` в состоянии `pending`. После `set_provisional` задача стоит в очереди VLM со `stage=vlm` и `status=queued`, пока VLM-воркер её не возьмёт ([architecture.md](architecture.md), раздел 4.2; [ADR-0007](adr/0007-ui-polling-sse-deferred.md), п. 3) |
| Готово, есть признаки | `status = done`, `verdict = violation` | Баннер вердикта, карточки, наблюдения |
| Готово, признаков нет | `status = done`, `verdict = no_violation` | Баннер вердикта, наблюдения (если есть) |
| Ошибка анализа | `status = failed` | Карточка ошибки по `error.code` и `error.message_ru`. Частичные результаты не показываем |
| Нет связи | Два запроса подряд упали | Полоса «Нет связи с сервером. Повторяем запрос…». Последние данные остаются на экране |
| Нужен код | 401 | Экран кода доступа |

Защита от нарушения инварианта: `status = done` и `verdict = null` — показываем ошибку `INTERNAL`, пишем `console.error`. Источник истины для вердикта — поле `verdict`, а не длина списка.

Повторная загрузка того же файла может сразу вернуть `done`: сервер кэширует результат по sha256. Первый же ответ опроса тогда содержит готовый результат, и шаги не показываются.

### 5.3 Шаги анализа (StageStepper)

Данные: `UiJobView.stages` — список `StageState{code, status, progress, elapsed_sec, note_ru}`. Коды: `queued`, `probe`, `perception`, `rules`, `evidence`, `vlm`, `done`. UI рисует шаги в порядке ответа сервера. Подпись шага берётся из `ru.ts` по коду. Неизвестный код выводится как есть.

| Статус шага | Значок | Подпись |
|---|---|---|
| `pending` | пустой круг | «ожидает» |
| `running` | индикатор + полоса `progress` | «выполняется» |
| `done` | галочка | «готово» + `elapsed_sec` |
| `skipped` | прочерк | «пропущено» + `note_ru` |
| `failed` | крестик | «ошибка» + `note_ru` |

Строка над шагами:
- `queued`: «В очереди. Перед вами: {queue_position}». Во время прогона жюри задания UI ждут: у них приоритет ниже.
- всегда: «Прошло {elapsed_sec}»;
- если есть `eta_sec`: «Осталось примерно {eta_sec}».

UI не считает прогресс сам и не интерполирует время между опросами: опрос раз в секунду и так выглядит живым.

Пропуск шага `vlm` — штатная деградация, а не ошибка. Причина приходит в `note_ru` и в `degradations`.

### 5.4 Предварительный результат

Сразу после правил сервер пишет полный предварительный результат и выставляет `provisional = true`. Затем VLM его уточняет. Так результат появляется без SSE.

Пока `status ∈ {queued, running}` и `provisional = true`:
- баннер «Предварительный результат: найдено {n} {признак/признака/признаков}. Идёт перепроверка, список может измениться.» Если признаков нет — «Предварительно признаков не найдено. Анализ продолжается.»;
- финальная формулировка вердикта из ТЗ не показывается до `status = done`;
- у карточек бейдж «Предварительно», у маркеров на шкале пунктирный контур;
- карточки ключуются по `id`, поэтому при обновлении не мигают.

После `done` бейджи исчезают (сервер присылает `provisional = false`), баннер становится финальным. Список может сократиться: ответ VLM «нет» понижает оценку признака. Добавиться может только `OTHER_VISIBLE_IRREGULARITY`, и то по отдельному решению команды ([architecture.md](architecture.md)).

### 5.5 Вердикт (VerdictBanner)

Показывается только при `status = done`. Вердикт берётся из поля `verdict`. UI его не вычисляет.

| `verdict` | Заголовок (дословно ТЗ) | Тон | Подзаголовок |
|---|---|---|---|
| `violation` | «Обнаружены признаки возможных нарушений» | красный, значок предупреждения | «Найдено: {n} {признак/признака/признаков}. Проверьте каждый фрагмент по кадрам и норме.» |
| `no_violation` | «Нарушение не обнаружено» | зелёный, значок галочки | «Сервис не нашёл видимых признаков нарушений. Это подсказка для проверки, а не гарантия их отсутствия.» |

Под заголовком всегда: «Результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение.»

Цвет никогда не единственный носитель смысла: есть значок и текст.

Бейдж деградации (`DegradedBadge`, файл `src/features/verdict/DegradedBadge.tsx`) показывается, если `result_level` не `full` или список `degradations` не пуст:
- бейдж «Упрощённая проверка»;
- `result_level = rules`: «Результат получен по правилам, без перепроверки VLM.»;
- `result_level = partial`: «Перепроверка VLM выполнена частично.»;
- ниже — каждая `degradations[].reason_ru` как есть.

Баннер — область `role="status"` с `aria-live="polite"`: итог объявляется скринридером один раз.

### 5.6 Карточка нарушения (ViolationCard)

Поля `UiViolation` и их место в карточке:

| Поле | Где | Как |
|---|---|---|
| `title_ru` | Заголовок карточки | Тот же текст, что в поле `type` ответа жюри |
| `timecode_sec` | Кнопка-чип «00:44,2» | Клик: «Показать в видео», [§5.9](#59-видео-и-шкала-событий-videoplayer-eventtimeline) |
| `start_sec`, `end_sec` | «Фрагмент 00:42,0–00:47,5» | Только если `end_sec > start_sec` |
| `description_ru` | Блок «Что видно» | Как есть, без правок и сокращений |
| `legal[]` | Блок «Правило и источник» | [§5.7](#57-правило-и-источник-legalreference) |
| `evidence[]` | Блок «Кадры-доказательства», 1–3 | [§5.8](#58-кадры-доказательства-evidencestrip-evidencelightbox) |
| `provisional` | Бейдж «Предварительно» | Только при `true` |
| `vlm_status` | Бейдж VLM | Таблица ниже |
| `code`, `confidence` | «Технические детали» карточки | Моноширинный код; «Оценка модели: 0,82» |

Порядок карточек — как в ответе (сервер сортирует по времени). Карточки нумеруются 1, 2, 3…; те же номера стоят на маркерах шкалы.

Бейдж `vlm_status`. Подсказка у бейджа: «VLM — локальная модель Qwen3.5-4B. Она перепроверяет признак по кадрам и может только снизить его оценку.»

| `vlm_status` | Текст бейджа |
|---|---|
| `confirmed` | «Подтверждено VLM» |
| `downweighted` | «Снижено VLM» |
| `unverified` | «Без подтверждения VLM» |
| `skipped` | «VLM не запускалась» |

Попадают ли сниженные VLM признаки в `violations` — проверить у S5 ([§16](#16-открытые-вопросы-проверить), вопрос 1). Пока правило такое: UI рисует то, что прислал сервер, и не фильтрует список сам.

`confidence` — внутренняя оценка модели, а не вероятность нарушения. Крупно её не показываем.

### 5.7 Правило и источник (LegalReference)

Для каждого `UiLegalRef{act_code, act_title_ru, clause, quote_ru, url, strength}`:
- название акта `act_title_ru` и короткая метка акта: ПКО, ПОП, ПОО, ТИБ;
- пункт `clause`, например «п. 20 ч. 2»;
- бейдж силы связи `strength`;
- кнопка «Показать текст нормы»: раскрывает `quote_ru` в `<blockquote>`. Цитата дословная, UI её не сокращает и не правит;
- ссылка «Открыть на adilet.zan.kz»: `url`, `target="_blank"`, `rel="noopener noreferrer"`. Рядом пометка: внешний сайт, во внутренней сети банка может не открыться. Цитата на месте, поэтому сайт для проверки не обязателен;
- ссылка «Все типы и нормы» ведёт на `/?view=types#<code>`.

Сила связи. Формулировки согласованы с описаниями, которые строит сервер ([legal_sources.md](legal_sources.md)):

| `strength` | Бейдж | Пояснение |
|---|---|---|
| `direct` | «Прямая норма» | «Пункт прямо описывает это действие.» |
| `indirect` | «Косвенная норма» | «Норма задаёт требование, нарушение следует из трактовки: может свидетельствовать о несоблюдении.» |
| `none` | «Прямой нормы нет» | «В проверенных актах прямой нормы нет, указана ближайшая.» |

Для `indirect` и `none` UI никогда не пишет «нарушен пункт». Пустой `legal[]` по контракту невозможен: контрактный тест требует норму у каждого кода. Если всё же пусто — «Норма не указана».

Включает ли `description_ru` юридическую фразу, как `description` в API жюри, — проверить у S5. Если включает, UI всё равно показывает описание как есть, а блок нормы отдельно. Описание не разбираем и не режем.

### 5.8 Кадры-доказательства (EvidenceStrip, EvidenceLightbox)

Миниатюры:
- `<img src={evidence.url} loading="lazy" decoding="async" width height alt>`, ширина и высота из `UiEvidence`, чтобы вёрстка не прыгала;
- подпись по `kind`: `event` — «Кадр события», `zoom` — «Увеличенный фрагмент», `context` — «Кадр до события»;
- под подписью — таймкод `timestamp_sec`;
- порядок — как в ответе;
- `alt`: «{вид кадра}, {таймкод}: {тип нарушения}»;
- картинка не загрузилась (например, удалена очисткой по сроку хранения) — заглушка «Кадр недоступен».

Лайтбокс:
- `yet-another-react-lightbox` с плагинами Zoom и Captions. Модуль и его CSS грузятся лениво (`React.lazy`) и в начальный бандл не попадают;
- чанк лайтбокса подгружается заранее при наведении или фокусе на миниатюре;
- открывается на выбранном кадре, листаются кадры этой карточки;
- подпись: «{тип} · {вид кадра} · {таймкод}»;
- масштаб: колесо, двойной клик или двойной тап, щипок, клавиши `+` и `−`. Стрелки листают. `Esc` закрывает, фокус возвращается на миниатюру;
- кнопка «Показать в видео»: закрывает лайтбокс и перематывает видео к `max(0, timestamp_sec − 2)`.

UI никогда не использует base64-кадры из API жюри. Только URL `/api/ui/jobs/{id}/frames/{name}` из ответа сервера.

### 5.9 Видео и шкала событий (VideoPlayer, EventTimeline)

Источник видео, по приоритету:
1. Серверное превью `video.url` (`UiVideo`), как только оно не `null`. Это H.264 MP4 с faststart, сервер отдаёт его с HTTP Range.
2. До этого, у того, кто загрузил файл в этой вкладке, — локальный object URL.
3. Ни того, ни другого — скелетон «Видео готовится…». HEVC-ролик с iPhone и повёрнутое видео сервер перекодирует, поэтому для них ожидание дольше.

Переключение с локального видео на серверное:
- локальное видео на паузе или закончилось — переключаем сразу и сохраняем позицию;
- локальное видео играет — переключаем при следующей паузе или переходе по таймкоду;
- локальное видео выдало `error` — переключаем на серверное, если оно есть, иначе заглушка.

Причина: таймкоды считаются по PTS на сервере. Браузер может показывать локальный .mov со смещением (edit list). Насколько велико смещение — проверить на Mac (S3/S6).

Элемент: `<video controls playsInline preload="metadata" muted>`.
- `muted`: звука в видео нет (FAQ 1), а `play()` после перемотки не блокируется политикой автозапуска;
- `playsInline`: на iOS видео не уходит в полноэкранный режим;
- `preload="metadata"`: телефон не тянет 29 МБ заранее.

Пропорции берутся из `video.width` и `video.height`. Типичный ролик — портрет 464×848. Финальный ролик может быть снят под другим углом и иметь другую ориентацию. Плеер целиком помещается в высоту окна.

Перемотка `seekTo(t)`:
- цель — `max(0, t − 2)`: проверяющий видит, что было за 2 секунды до события. Точный момент показывает кадр-доказательство;
- если `readyState < HAVE_METADATA`, перемотка ставится в очередь до `loadedmetadata`. Без этого Safari и iOS её игнорируют;
- затем `play()`; отказ промиса ловится;
- на телефоне после перемотки плеер прокручивается в видимую область (`scrollIntoView({block: 'nearest'})`).

Шкала событий `EventTimeline` под видео:
- длительность — из `video.duration_sec`, поэтому маркеры видны до загрузки метаданных;
- позиция маркера — `t / duration × 100 %`, с ограничением 0–100 %;
- маркеры нарушений красные, с номером карточки; маркеры наблюдений янтарные; предварительные — с пунктирным контуром;
- если `end_sec > start_sec`, под маркером полупрозрачная полоса интервала;
- маркеры ближе 1,5 % ширины шкалы (на сенсорных экранах — ближе 44 px) собираются в один маркер «{n} событий». Клик открывает список (Radix Popover);
- клик по маркеру — `seekTo(t)` и короткая подсветка карточки;
- клик по пустому месту шкалы ничего не делает: для перемотки есть штатные элементы видео;
- линия текущей позиции обновляется через `requestVideoFrameCallback`, при его отсутствии — через `timeupdate` (`useVideoClock.ts`);
- под шкалой легенда: «Признак нарушения», «Наблюдение», «Предварительно»;
- расчёт позиций, ограничение и кластеризация — чистые функции в `markers.ts`, покрытые unit-тестами.

Видео нет, а задание готово (превью не собралось) — шкала скрывается, текст: «Видео недоступно для просмотра. Ориентируйтесь на кадры-доказательства.»

### 5.10 Наблюдения (SignalList)

- Аккордеон «Наблюдения (не влияют на вердикт)» с количеством, по умолчанию свёрнут.
- Пояснение: «Наблюдения показаны для контекста. Они не учитываются в вердикте и не передаются в API жюри.»
- Элемент: `title_ru`, чип таймкода `t_sec` (перемотка), `description_ru`, миниатюры кадров (тот же лайтбокс).
- Оформление нейтральное или янтарное, никогда не красное. В счётчик баннера наблюдения не входят.
- Сигналы — это 13 кодов `SIG_*`. Их тексты сформулированы как «не наблюдается…» и приходят с сервера.

### 5.11 Технические детали

Свёрнутый блок `<details>` «Технические детали»:
- режим анализа `perception_level`: `full` — «полный», `fast` — «ускоренный», `min` — «минимальный»;
- уровень результата `result_level`: `full` — «правила и VLM», `partial` — «VLM частично», `rules` — «только правила»;
- время этапов из `timings`, в секундах;
- полный `job_id`.

Зачем: прозрачность для жюри (критерий «Техническое решение») и отладка. Внутренних путей, ключей и логов здесь нет.

### 5.12 Ошибки и сбои

| Ситуация | Как узнаём | Что показываем |

| `INTERNAL` | «Внутренняя ошибка сервиса» |

## 6. Экран «Типы нарушений и нормы» (TypesPage)

Зачем: ТЗ, раздел 8, требует перечень распознаваемых типов и нормативных источников. Экран показывает его в UI. Документ — `docs/violation_types.md` (генерируется `scripts/render_docs.py`, появится в P3).

Данные: `GET /api/ui/catalog` → `UiCatalog{config_hash, types[], signals[], acts[]}`.

Состав сверху вниз:
1. Вступление: какие типы распознаёт сервис; что такое прямая, косвенная норма и «прямой нормы нет»; только акты РК; результат — подсказка для проверки человеком.
2. Поле «Найти тип или пункт». Фильтр на клиенте по `title_ru`, `code`, `clause`, названию акта. Пустой результат — «Ничего не найдено».
3. Типы, сгруппированные по `group`, в порядке: `leave`, `access`, `cashops`, `collection`, `discipline`, `presence`, `other`. Карточка типа:
   - `title_ru` как `<h3 id="<code>">` — якорь для ссылок из карточек нарушений;
   - `code` мелким моноширинным шрифтом;
   - бейдж `verdict_impact`: «Влияет на вердикт» или «Не влияет на вердикт»;
   - нормы через тот же `LegalReference`, цитаты свёрнуты.
4. «Наблюдения (не влияют на вердикт)»: список `signals[].title_ru` и пояснение, что в API жюри они не попадают.
5. «Нормативные акты»: таблица `acts[]` — название, номер и дата, рег. номер, ссылка на adilet, статус. Акты со статусом «утратил силу», если сервер их присылает, идут отдельным списком «Утратили силу — не цитируются». Значения `status` — проверить у S0.

Поведение:
- экран — отдельный ленивый чанк;
- при загрузке — скелетоны; ошибка — «Не удалось загрузить каталог.» + «Повторить»;
- при `#<CODE>` в URL — прокрутка к типу и подсветка карточки.

Краткого описания типа в `UiCatalog` нет. Если оно нужно на экране — добавить поле в контракт через PR S0 ([§16](#16-открытые-вопросы-проверить), вопрос 4). Самому UI описания не сочинять.

## 7. Недавние проверки, индикатор готовности, код доступа

### 7.1 Недавние проверки (RecentJobs)

- Папка `src/features/recent/`. Хранилище — `localStorage`, ключ `cashguard.recent.v1`.
- До 10 записей, новые сверху, без дублей. Запись: `{id, fileName, createdAt, lastStatus, verdict, nViolations}`.
- Каждое чтение и запись — в `try/catch`. Хранилище недоступно (приватный режим, запрет) — блок не показывается, остальное работает.
- Запись обновляется после успешной загрузки и при каждом новом статусе на JobPage. Статусы списка с сервера не опрашиваются.
- Строка: имя файла (или «Видео без имени»), дата и время, чип статуса. Клик открывает `/?job=<id>`.
- «Убрать» у строки и «Очистить список» для всего блока.
- Пустой список: «Здесь появятся ваши проверки. Список хранится только в этом браузере.»

| Статус записи | Чип |
|---|---|
| `queued`, `running` | «Идёт анализ» |
| `done` + `violation` | «Обнаружены признаки» |
| `done` + `no_violation` | «Нарушение не обнаружено» |
| `failed` | «Не выполнено» |
| получен 404 | «Удалено» |

Серверной истории нет (FAQ 27). Чужие задания UI не видит и не перечисляет.

### 7.2 Индикатор готовности (ReadyDot)

- Папка `src/features/health/`, компонент в подвале.
- Источник — `GET /ready` → `ReadyReport{ready, checks{…}, vlm_quant, version}`. Ответ 503 — тоже валидные данные: в теле список проваленных проверок.
- Опрос раз в 30 с (оценка) и только пока вкладка видима.

| Состояние | Точка | Текст |
|---|---|---|
| `ready = true` | зелёная | «Сервис готов» |
| `ready = false` | янтарная | «Сервис запускается или перегружен» |
| Запрос не прошёл | серая | «Нет связи с сервером» |

Подсказка у точки: проваленные проверки по-русски и `vlm_quant`. Метки проверок:

| Проверка | Метка |
|---|---|
| `worker_perception` | «Модуль обнаружения объектов» |
| `worker_vlm` | «Модуль VLM» |
| `models_loaded` | «Модели загружены» |
| `warmup_done` | «Прогрев моделей» |
| `free_mem_ok` | «Свободная память» |
| `disk_ok` | «Место на диске» |
| `queue_ok` | «Очередь не переполнена» |

На экране загрузки при `ready = false`: «Сервис сейчас не готов: анализ может начаться позже обычного.» Загрузка не блокируется: задание после ответа 200 не теряется и дождётся очереди.

### 7.3 Код доступа (KeyGate)

- По умолчанию выключен: FAQ 27, настройка `CG_UI_ACCESS_CODE` не задана.
- UI узнаёт о включённом коде по ответу 401 от любого `/api/ui/*`. Код ответа — проверить у S1.
- Экран: поле «Код доступа», кнопка «Войти». `POST /api/ui/session {code}` — сервер ставит cookie `HttpOnly`, `SameSite=Strict`. Затем UI повторяет исходный запрос.
- Код не хранится в JS-состоянии дольше отправки, не пишется в `localStorage` и не попадает в URL.
- Cookie на том же origin уходит автоматически: в XHR, в `<video>`, в `<img>`.
- Папки для `KeyGate` в FOLDER_TREE нет. Предложение — `src/features/access/KeyGate.tsx`, согласовать с S0.

| `GET /api/ui/jobs/{id}/video.mp4` | `<video src>` | Плеер | HTTP-кэш браузера, Range, `private, max-age=3600` |
| `GET /api/ui/jobs/{id}/frames/{name}` | `<img src>` | Карточки, лайтбокс | `private, max-age=31536000, immutable` |
| `GET /ready` | `useReady` | Подвал | Опрос 30 с (оценка), только видимая вкладка |
| `POST /api/ui/session` | `KeyGate` | Только при включённом коде | — |

Никогда: `/api/v1/*`, заголовок `X-API-Key`, `/api/v1/admin/status`, `/api/ui/jobs/{id}/events` (SSE зарезервирован, в v1 его нет).

### 8.2 Клиент

- `src/shared/api/client.ts` — `createClient<paths>()` из `openapi-fetch`, относительные пути, тот же origin. CORS не нужен.
- `src/shared/api/queries.ts` — хуки `useCatalog`, `useJob`, `useReady` и ключи запросов: `['catalog']`, `['job', id]`, `['ready']`.
- `src/features/upload/uploadVideo.ts` — XHR-загрузка. Тип ответа берётся из `schema.d.ts`.
- Типы — только из `schema.d.ts`: `components['schemas']['UiJobView']` и т. п. Ручных копий типов API нет.
- URL видео и кадров берутся из ответа (`video.url`, `evidence[].url`). UI не собирает пути сам.

### 8.3 Опрос задания

Опрос раз в секунду, пока задание `queued` или `running`. Ответ — около 0,5 КБ. На сервере такой запрос стоит до 2 мс. В фоновой вкладке опрос не останавливается: трафик ничтожный, а заголовок вкладки должен смениться на «Готово».

```ts
const isActive = (s?: string) => s === 'queued' || s === 'running';

useQuery({
  queryKey: ['job', jobId],
  queryFn: fetchJob,                       // openapi-fetch, GET /api/ui/jobs/{job_id}
  enabled: isValidJobId(jobId),
  refetchInterval: (q) =>
    isHttpError(q.state.error, 404, 401) ? false
      : q.state.data && !isActive(q.state.data.status) ? false
      : 1000,
  refetchIntervalInBackground: true,
  staleTime: (q) => (q.state.data && !isActive(q.state.data.status) ? Infinity : 0),
  retry: (n, err) => !isHttpError(err, 404, 401) && n < 2,
});
```

Общие настройки `QueryClient`: `refetchOnWindowFocus: false`. Каталог: `staleTime` и `gcTime` — `Infinity`.

Хук `useJob` не раскрывает транспорт. Если в P3 включат SSE (`CG_UI_SSE=1`), он встанет внутрь того же хука с откатом на опрос, и компоненты не изменятся.

### 8.4 Что UI вычисляет сам

Только представление: форматы времени и размеров, формы множественного числа, позиции маркеров, фильтр на экране типов. Вердикт, состав нарушений, тексты описаний и норм UI не вычисляет и не переписывает.

Правила:
- без SSR, без роутера, одна статическая сборка в `web/dist`; FastAPI отдаёт `index.html` с `no-cache`, а `/assets/*` с `immutable`;
- шрифты только системные, веб-шрифтов нет; для таймкодов `font-variant-numeric: tabular-nums`;

- у картинок явные `width` и `height`, `loading="lazy"`;
- скелетоны вместо спиннеров;
- первая отрисовка не ждёт каталог;
- опрос не перерисовывает неизменившиеся части: в TanStack Query структурное разделение включено по умолчанию; шкала событий мемоизирована;
- base64 в UI нет.

Как мерить: вывод `pnpm build` (размеры чанков); Playwright против публичного URL; DevTools с ограничением сети. Рост начального чанка больше чем на 20 % — обсудить с S0 до мерджа.

## 10. Адаптивность и телефоны

- Брейкпоинты — стандартные Tailwind. Раскладка меняется на `lg`: две колонки на десктопе, одна на телефоне.
- Телефон: одна колонка, поля 16 px по бокам, зоны касания не меньше 44 px, без горизонтальной прокрутки.
- Плеер на телефоне не прилипает: портретное видео заняло бы весь экран.
- На телефоне после «Показать в видео» плеер прокручивается в видимую область.
- Маркеры шкалы на сенсорных экранах получают невидимую зону касания 44 px и кластеризуются ([§5.9](#59-видео-и-шкала-событий-videoplayer-eventtimeline)).
- Выбор файла: `accept="video/quicktime,video/mp4,.mov,.mp4"` — на iPhone доступна «Медиатека».
- iOS: `playsInline`, перемотка после `loadedmetadata`; Range сервер уже отдаёт.
- Лайтбокс на телефоне — на весь экран, со щипком и свайпом.
- Во время загрузки: «Не закрывайте вкладку до конца загрузки».
- Проверяемые размеры: Pixel 7 (Chrome, Windows) и iPhone (WebKit, Mac) из устройств Playwright.

## 11. Доступность

Цель — WCAG 2.1 AA. Это решение S2, в ТЗ его нет.

- `<html lang="ru">`. Ориентиры: `header`, `nav`, `main`, `footer`. Один `<h1>` на экран.
- Всё доступно с клавиатуры. Зона загрузки — кнопка, открывает выбор файла по Enter и пробелу. Порядок табуляции совпадает с визуальным.
- Видимый фокус у всех интерактивных элементов.
- Полосы прогресса: `role="progressbar"` с `aria-valuenow`, `aria-valuemin`, `aria-valuemax` и текстом.
- Смена шага и итог объявляются через `aria-live="polite"`, без повторов на каждом опросе.
- Маркеры шкалы — `<button>` с `aria-label`: «Нарушение: {тип}, {таймкод}» или «Наблюдение: {тип}, {таймкод}». Шкала — `role="group"` с меткой «Шкала событий». Линия позиции — `aria-hidden`.
- У каждой миниатюры есть `alt` ([§5.8](#58-кадры-доказательства-evidencestrip-evidencelightbox)). Лайтбокс работает с клавиатуры и возвращает фокус.
- Цвет не единственный признак: вердикт, нарушения и наблюдения различаются значком и текстом.
- Контраст текста — не ниже 4,5:1.
- `prefers-reduced-motion`: без анимаций переходов и подсветки.
- Ошибки — текстом в странице, рядом с местом ошибки, а не только toast.
- Видео со штатными `controls`. Звука нет, поэтому субтитры не нужны.
- После перехода между экранами фокус переходит на `<h1>`.
