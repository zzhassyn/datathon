## Как пользоваться

- Агент находит свою сессию (раздел 4) и свои карточки (раздел 5). Берёт карточку, только когда закрыты все её зависимости.
- Карточка закрыта, когда выполнена её «Приёмка» и DoD задачи (раздел 7).
- Время — относительные часы `Ч+N` от старта P0 (раздел 6). Все длительности — оценка, если не написано «замер».
- Пути — из дерева папок архитектуры ([structure.md](structure.md)). Путь, которого в дереве нет, помечен «новый путь».
- Решения по архитектуре — в [architecture.md](architecture.md) и [ADR](adr/README.md). При расхождении с этим документом прав ADR; roadmap отвечает только за порядок, владельцев и приёмку.

## 0. Контрольные точки совместной проверки K0–K4

Проверяем по готовым сценариям, а не по числу файлов. На каждой точке frontend и backend делают commit и push в свои ветки и присылают commit, результаты проверок и что не проверено. Интегратор (backend) сводит ветки в `main` fast-forward-ом, без force push.

| Точка | Frontend | Backend | Что проверяем вместе |
|---|---|---|---|
| **K0: контракт** | перенос интерфейса, перечень нужных полей | согласованные схемы (`contracts/ui.py`, `web/src/shared/api/openapi.json`) и примеры `tests/fixtures/ui/*.json` | одинаково ли понимаем результат |
| **K1: загрузка** | выбор файла, отправка, страница задания | приём файла, очередь, статусы | загрузка из браузера создаёт настоящее задание |
| **K2: результат** | видео, события, контекст, кадры, источники | полные тестовые результаты и media-маршруты (`video.mp4` с Range, кадры) | чистый ролик и несколько событий отображаются правильно |
| **K3: устойчивость** | ошибки, повторные действия, восстановление страницы | таймауты, перезапуск, сбои воркера | система не теряет задание и не выдаёт ложный успех |
| **K4: модели** | отображение реального ответа | подключён реальный пайплайн | сквозная проверка на отложенных видео |

Тестовый пайплайн (`pipeline_mode: "stub"`) обозначен явно в API и интерфейсе и никогда не выдаёт «нарушений нет» для неизвестного реального видео: такое видео получает `failed` с понятной ошибкой.

## 1. Цель и карта баллов

**Цель.** К дедлайну (FAQ 33: «В 12:00», дата — проверить) сдать жюри публичный URL с UI, API по ТЗ §10 и ключ. На любое видео `.mov` около 29 МБ сервис за ≤ 5 минут отдаёт вердикт, а для каждого нарушения — тип, таймкод, 1–3 кадра, описание и норму РК. Всё считается локально на MacBook Pro M2 Pro 16 ГБ, без облачных AI-сервисов.

**Главное ограничение.** Пропуск нарушения недопустим, ложных срабатываний — как можно меньше (FAQ 16). Видео без ответа за 5 минут считается необработанным (ТЗ §10). Поэтому порядок приоритетов: ответ вовремя и по схеме → recall по видео → тип и таймкод → точность.

### 4.2. Что идёт параллельно

- После мержа контрактов (≈ Ч+2,5) параллельно работают S1, S2, S3 (Windows), S4, S5, S6 (Windows). Они пересекаются только через контракты.

### 4.5. Правила при конфликтах

- У папки один владелец. Чужой файл — только через PR владельцу или через S0.
- Одно правило, одна запись каталога, одна норма, один бэкенд — один файл. Реестр правил находит их через pkgutil, центрального списка нет.
- Контракты меняет только S0. Замороженную схему жюри — только с одобрения человека.
- `uv.lock`: при конфликте взять версию из `main` и выполнить `uv lock`. `pnpm-lock.yaml`: выполнить `pnpm install`. Руками lock-файлы не мержить.
- Новая зависимость — только через S0.
- Сгенерированные файлы не править: `contracts/schemas/generated/*`, `web/src/shared/api/{openapi.json,schema.d.ts}`, `docs/violation_types.md`.
- Каталог: v0 пишет S0; дальше шаблоны и пороги — владелец кода (P1–P2), нормы — S5, и только в P3-S5-01. Так правки одного `configs/catalog/<CODE>.yaml` не пересекаются по времени. Карточки кодов в [violation_catalog.md](violation_catalog.md) правит только S0 по PR владельцев (позже эта часть генерируется).
- `eval/baselines/main.json` правят не PR правил. PR правил прикладывают только дифф `just eval-replay`. После каждого мержа S1 одним последовательным PR перегенерирует базовую линию (`cashguard eval --update-baseline`; имя флага — проверить с S1).
- `configs/rules/<CODE>.yaml` правит только владелец кода. τ_final S5 публикует таблицей по итогам `eval-full` (P3-S5-01), а владельцы переносят значения в свои файлы.
- `justfile` ведёт S0; рецепты других сессий приходят PR-ом.
- Мерж — только fast-forward, выполняет S0.
- `training/` до P0-S0-01 правит только сессия обучения; после — S3, и только аддитивными PR, согласованными с автором сессии обучения. Скрипты `training/scripts/00–12` и `run_stage_*.sh` не переписываются: экспорт для сервиса делает отдельный экспортёр `pipeline/perception/export.py`.

### 4.6. Схема на 4 сессии

Если 7–9 параллельных сессий не тянем: S4 + S5 = «все правила», S3 + S6 = «весь Mac». Номера карточек не меняются; в колонке «Сессия» читать объединённую.

### 4.7. Жёсткие правила для агентов

Полный список — в [../AGENTS.md](../AGENTS.md). Коротко:
- Никаких облачных AI-вызовов в коде пайплайна.
- Не открывать видео и кадры датасета и жюри (deny-правила в `.claude/settings.json`, на Mac — ещё в `~/.claude/settings.json` с абсолютными путями). Агенты работают с кодом, метриками и числовыми трассами. Полный ответ jury API с base64-кадрами в терминал не выводить (`scripts/smoke_jury.sh` пишет его в `var/smoke/`).
- Не коммитить `data/`, `var/`, `models/`, `runs/`.
- Не ставить `fastapi[standard]`, TypeScript 7, react-router, msw. Не использовать `OBJC_DISABLE_INITIALIZE_FORK_SAFETY`.
- Не заменять потоковую загрузку на `UploadFile`, всегда передавать трекер явно, таймкоды брать только из PTS.

### 6.4. Правила при сдвиге

- Этап B не укладывается к Ч+8,5 → запускаем этап C на кадрах, проверенных к этому моменту (≥ 600). Правку продолжаем; второе обучение — ночью вместо RF-DETR.
- Код восприятия не готов к Ч+6,5 → трассы v0 не снимаются (P1-S3-04 пропускается). G1 идёт на синтетических трассах; первые реальные трассы — v1 (P2-S3-04). Этап C не ждёт.
- Этап C не помещается в память → `PROFILE=full_m` или `--batch 4` (время растёт, оценка).
- Паритет Core ML хуже 1 mAP50 или экспорт падает → изолированное окружение с torch 2.8. Если не помогло — остаёмся на детекторе v001 и пишем это в [limitations.md](limitations.md).
- VLM не проходит гейт 3 ГБ даже на 4 битах → `CG_VLM_ENABLED=false`, rules-only, запись в [limitations.md](limitations.md).
- `jury-sim` N = 10 не укладывается в 300 с → настраиваем уровень `min` и рубеж `perception_hard_stop` в `configs/deadlines.yaml` (S1), а не записываем провал в ограничения.
- Mac-окна Ч+23 – 26 не вмещают все `eval-full` → `perf` и репетиция сдвигаются, тег — не позже Ч+32 (ниже).
- Нет домена к концу P0 → Tailscale Funnel становится основным URL; 5 параллельных загрузок по 29 МБ через Funnel проверяются в P4-S6-02.
- Тег не готов к Ч+30 → крайний срок Ч+32; репетиция №2 сокращается до чек-листа T-1h.
- Mac недоступен → резервный Docker rules-only на RTX 3050 (P4-S1-01), только после остановки коннектора Mac.

## 7. Definition of Done и гейты качества

### 7.1. DoD задачи

1. Изменены только файлы своих папок. Чужие файлы — PR владельцу или через S0.
2. Выполнена «Приёмка» карточки; вывод команд вставлен в описание PR.
3. Ветка сделала rebase на `main`, `uv run just check` зелёный.
4. Контракты не менялись, или их изменение ушло отдельным PR раньше.
5. Новое или изменённое правило: фикстуры pos и neg, запись каталога с нормой (цитата дословно есть в `analysis/normative/`), снапшот шаблона описания, дифф `uv run just eval-replay` против `eval/baselines/main.json`.
6. В коммите нет данных, весов, видео, кадров, ключей, полных ответов jury API (`data/`, `var/`, `models/`, `runs/`, `result_*.json` в `.gitignore`; хук `check-added-large-files`).
7. Нет новых зависимостей без S0; сгенерированные файлы не правились руками.
8. Задача на Mac: релевантные `uv run pytest -m mac` зелёные на Mac; замеры записаны в конфиг или отчёт. Если Mac недоступен, в PR прямо сказано, что не проверено на Mac.
9. Изменилось поведение → обновлён документ зоны (`docs/*.md` или `src/cashguard/<module>/AGENTS.md`).

### 7.2. DoD релиза `jury-v1`

1. Пройдены все условия G4 (раздел 3).
2. Тег `jury-v1` стоит на коммите, который работает на Mac; `uv sync --locked` и `pnpm build` выполнены из тега.
3. Модели совпадают с `configs/models.yaml` по sha256; воркеры стартуют офлайн (`HF_HUB_OFFLINE=1`, `YOLO_OFFLINE=1`).
4. Две репетиции со сбоями пройдены (одна — на теговой сборке).
5. Документы закрывают ТЗ §8 один к одному (таблица 2.4); в README — URL UI, URL API, резервный URL, инструкция, оговорка AGPL.
6. Ключи сгенерированы, ключ жюри передан, в git его нет.
7. Mac в режиме жюри: питание, крышка открыта, Ethernet, автообновления выключены, посторонние приложения закрыты, дежурный назначен ([jury_mode.md](jury_mode.md)).
