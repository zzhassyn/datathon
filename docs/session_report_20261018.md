## Что умеет workflow

Цепочка: PyAV (PTS) → YOLO26s main/hands (CPU, 2 fps) + BoT-SORT без ReID → автозоны по
объектам → история сцены → правила → описание из каталога норм → кадры-доказательства.

Правила, включённые в конфиге (`temporal_rules.codes`):
- `VALUABLES_LEFT` — ценности оставлены при уходе (деньги на столе, кассир вышел);
- `SAFE_OPEN` — логика есть, детектор не даёт `safe_open` (см. пропуски);
- `THIRD_PERSON_DURING_SERVICE` — второй посетитель у стола во время обслуживания.

Остальные коды каталога не оцениваются; при полном анализе без кандидатов сервис
возвращает `no_violation`, основание — в `technical_scope.json` задания. Если предметы
стола не обнаружены (другая сцена), тоже `no_violation` с причиной
`scene_not_recognized`, а не ошибка. Это решение для контракта жюри (два вердикта).

Новое в этой сессии (код):
- `scene/auto_zones.py`: стол, дверь, сейф, место кассира по медианам детекций; кассир —
  трек с наибольшим перекрытием стола. Ручная калибровка под каждое видео не нужна.
- `scene/temporal.py`: ослабленный выход (`exit_mode: relaxed`): трек кассира заканчивается
  у двери/края кадра, после этого в комнате никого до конца ролика; уверенность 0.55.
- `rules/access/third_person_during_service.py`: ≥2 не-кассира у стола ≥2 с; исключены
  место кассира (IoU>0.5), дубли рамок, мелкие рамки за стеклом двери.
- `windows_analysis.py`: режим auto_zones, чистый вердикт, ограничение интервала
  длительностью видео (без этого публикация падала).
