# ADR-0007. Прогресс в UI — опрос раз в секунду с прогрессивными промежуточными результатами; SSE отложен

> Назначение: зафиксировать, как веб-интерфейс узнаёт о ходе обработки.
> Владелец: S0 (документ); реализуют S2 (`web/src/shared/api/queries.ts`, `features/progress/`) и S1 (`api/views.py`, `api/routes/ui.py`). Статус: черновик v1, 17.10.2026.

## Статус

Принято. SSE — опциональное улучшение P3, в v1 не реализуется.

## Контекст

- ТЗ §4: сервис отображает статус обработки. Критерий «Готовность продукта» (10 баллов) оценивает удобство и понятность.
- Этапы длятся секунды: промежуточный результат для типичного ролика ≤ 7–10 с, финальный ≤ 25–35 с (оценка).
- Cloudflare Quick Tunnel не поддерживает SSE. Именованный туннель зависит от домена, которого может не быть (открытый вопрос, [ADR-0013](0013-public-ingress-tunnel.md)).
- Жюри использует опрос. Общий путь проще поддерживать и тестировать.
- Долгие соединения мешают аккуратной остановке uvicorn (`--timeout-graceful-shutdown 30`).

## Решение

1. **Опрос.** TanStack Query `refetchInterval: 1000` мс, пока задача `queued` или `running`, на `GET /api/ui/jobs/{id}`. После `done` или `failed` опрос останавливается, `staleTime: Infinity`.
2. **Лёгкий ответ.** `UiJobView` во время обработки ≈ 0,5 КБ: этапы (`StageState`), позиция в очереди, `eta_sec`, уровни perception и результата, деградации. Источник — одна индексированная строка SQLite (≤ 2 мс на origin, оценка).
3. **Прогрессивный результат.** Как только у задачи появился `provisional_at`, ответ несёт нарушения с `provisional: true`. UI показывает бейдж «Предварительно». После VLM карточки обновляются; пониженные кандидаты помечаются «снижено VLM».
4. **Полный результат** при done — из кэша `ui_result.json` в API (LRU по mtime).
5. **SSE зарезервирован** на P3:
   - маршрут `GET /api/ui/jobs/{id}/events`, включается `CG_UI_SSE=1`, только за именованным туннелем;
   - `fastapi.sse.EventSourceResponse`, протокол «сначала снимок»: `event: snapshot` (= `UiJobView`), затем `stage`, `provisional`, `done|failed`; ping каждые 15 с; `retry: 3000`;
   - сторож на клиенте: нет снимка за 4 с или 2 события `onerror` — возврат к опросу раз в секунду.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| SSE как основной транспорт с дельта-опросом как запасным | Зависит от именованного туннеля. Добавляет контракты (таблица событий, насос событий) на критический путь |
| WebSockets | Логика переподключения, сложнее через прокси и туннели, не нужен двусторонний канал |
| Глобальная таблица событий с насосом событий | Лишний механизм и лишние записи в SQLite ради выигрыша меньше секунды |

## Последствия

Плюсы:
- Работает через любой вход: именованный туннель, Funnel, quick tunnel.
- Нет логики переподключения. Чистая остановка сервера.
- Тот же путь данных, что у жюри. Один набор тестов.
- Прогрессивные карточки сохраняют главное преимущество «живого» интерфейса.

Минусы и цена:
- Задержка обновления до 1 с.
- ≈ 1 запрос в секунду на открытую вкладку с активной задачей. На origin это дёшево, но лимиты UI должны это учитывать (опросы не лимитируются как загрузки).

Что проверяет решение:
- Vitest: хук `useJob` (интервал, остановка, переход в `staleTime: Infinity`).
- Playwright: `upload.spec.ts`, `result.spec.ts` против FastAPI в режиме stub; появление бейджа «Предварительно».
