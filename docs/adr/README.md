## Правила ведения

1. Одно решение — один файл `NNNN-<slug>.md`. Номера сквозные, не переиспользуются.
2. Шаблон разделов: **Статус**, **Контекст**, **Решение**, **Рассмотренные альтернативы**, **Последствия**. В начале — шапка из 2–3 строк: назначение, владелец (сессия S0–S6), статус документа.
3. Статусы: «Предложено», «Принято», «Заменено ADR-NNNN». Принятое решение не переписывается задним числом: новое решение — новый ADR со ссылкой на старый.
4. Факты — только из источников (ТЗ и FAQ, [case_analysis.md](../../analysis/case_analysis.md), [detection_design.md](../../analysis/detection_design.md), синтез архитектуры). Непроверенное помечается «проверить», оценки — «оценка».
5. Ссылки на нормы РК — только из раздела 7 [case_analysis.md](../../analysis/case_analysis.md) с цитатами из `analysis/normative/*.txt`.
6. ADR пишет и вливает S0. Изменение замороженного контракта жюри ([0006](0006-frozen-jury-contract.md)) — только с одобрения человека.
