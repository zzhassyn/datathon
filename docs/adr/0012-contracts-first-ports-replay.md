# ADR-0012. Сначала контракты: порты с бэкендами stub, replay и null; трассы replay только из чисел

> Назначение: зафиксировать, как шесть агентских сессий работают параллельно без Mac и без доступа к кадрам.
> Владелец: S0 (`contracts/**`, `pipeline/runner.py`, `pipeline/rules/{base,registry,context}.py`); затрагивает всех. Статус: черновик v1, 17.10.2026.

## Статус

Принято.

## Контекст

- Код пишут 6 агентских сессий (S1–S6) плюс интегратор S0 в параллельных worktree на Windows.
- Mac один, и он же занят обучением ([ADR-0002](0002-three-process-runtime-supervisor.md), режимы serve/train/dev).
- Политика данных: облачные агенты не смотрят кадры датасета и жюри. ТЗ §7 запрещает передавать кадры облачным AI при обработке; FAQ 6 ограничивает использование данных. Безопаснее, чтобы кадры смотрели люди ([detection_design.md](../../analysis/detection_design.md)).
- Настройка порогов правил требует быстрых итераций по 40 роликам.
- Нужен перенос на Linux + CUDA (ТЗ §7).

## Решение

1. **Порты** (`contracts/ports.py`, `typing.Protocol`): `VideoSource`, `PerceptionBackend`, `FrameStore`, `Rule`, `SignalRule`, `VlmBackend`, `ProgressFn`, `Clock`.
2. **Режимы и бэкенды:**
   - `CG_PIPELINE_MODE` = `stub` | `replay` | `full`;
   - `CG_VISION_BACKEND` = `coreml` | `torch` | `replay` | `stub` | `null`;
   - `CG_VLM_BACKEND` = `mlx` | `transformers` | `replay` | `null`.
   Режим `stub` (`pipeline/stub.py`) даёт детерминированный результат по подсказке в имени файла — для API, UI и E2E без моделей.
3. **Сигнатуры этапов заморожены на P0** в `pipeline/runner.py` ([architecture.md, раздел 5.11](../architecture.md#511-функции-этапов)). Владельцы реализуют функции, не меняя сигнатур.
4. **Трассы replay:**
   - Mac извлекает `PerceptionTrace` один раз на версию моделей: `just extract-signals` → `var/signals/<sha16>__<models_hash>.json.gz`; ответы VLM записываются для replay-бэкенда;
   - `just sync-signals` копирует их по scp через LAN или Tailscale на Windows; никогда через облачные хранилища;
   - трассы содержат только числа: боксы, классы, треки, состояния;
   - `just eval-replay` прогоняет scene → rules → verdict по 40 трассам за секунды.
5. **Чистые слои.** `pipeline.scene`, `rules`, `verdict`, `legal`, `render` — чистый Python + numpy; import-linter запрещает им ML-импорты. Подпакеты `rules.*` не зависят друг от друга.
6. **Один файл — одна сущность:** правило, запись каталога, норма, бэкенд. Регистрация через `@register_rule` и pkgutil — центрального списка нет.
7. **Изменение контракта** — отдельный маленький PR, вливается первым; зависимые ветки делают rebase.
8. **Золотые ворота для PR с правилом:** дифф `just eval-replay` против `eval/baselines/main.json`; LOSO recall по видео 1.0; precision, точность типа и медиана |Δt| в допуске; ни одного нового срабатывания вердиктных кодов на чистых роликах; позитивный и негативный фикстур таймлайна; запись каталога с нормой, цитата которой дословно есть в `analysis/normative`; снапшот шаблона.
9. **Данные:** правила deny в `.claude/settings.json` (`Read(./data/**)`, `Read(./var/**)`, `Read(./models/**)`, `Read(**/*.mov)`) и запрет в `AGENTS.md`.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Реальный perception на каждое изменение правил | Mac — узкое место и занят обучением; минуты на прогон вместо секунд |
| Разрешить агентам смотреть кадры для отладки | Нарушает политику данных; серая зона по ТЗ §7 и FAQ 6 |
| Монолитный `app.py` | Постоянные конфликты слияния между параллельными сессиями |

## Последствия

Плюсы:
- Четыре из шести сессий (S1, S2, S4, S5) не нуждаются в Mac и в кадрах.
- eval-replay по 40 роликам — секунды.
- Политика данных обеспечена механически.
- Бэкенды Linux (`torch`, `transformers`) подключаются без изменений остального кода.

Минусы и цена:
- Трассы устаревают при смене моделей: после продвижения обученных моделей нужен повторный `extract-signals` (v1 после ворот G2).
- Replay не ловит ошибки, которые проявляются только в живом perception. Поэтому в P3 обязательны `just eval-full`, `perf` и `robustness` на Mac.
- Контракты становятся узким местом. S0 должен вливать их быстро.

Что проверяет решение:
- import-linter и проверка дрейфа контрактов в `uv run just check`.
- `tests/contract`: замороженная схема, дрейф OpenAPI, дословность цитат, полнота каталога.
- `just eval-replay` на каждом PR с правилом.
