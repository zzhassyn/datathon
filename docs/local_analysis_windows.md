# Локальный Windows-срез анализа

Основной `/api/ui/jobs` подключён к SQLite worker и настоящим PT-моделям. Это
ограниченный технический срез `PERSONAL_ITEMS`, а не выпуск всех правил для жюри.
`stub` остаётся явно отдельным режимом. `replay` и Mac-adapters этим изменением
не объявляются готовыми. Публичные jury/UI схемы не изменены.

## Модели

- Main: CashGuard YOLO26s, 14 классов, best22, SHA-256
  `b687a1e38127ae637ed1e9d9163da192dff82c2123bc63064ac5950a19cf12fb`.
- Hands: CashGuard YOLO26s, class0=hand, best27, SHA-256
  `544f49d455934b703e6516cc9139bed0fee1b7a4aaf2a3c495451004769c4dfc`.
- Door: YOLO26s-cls, closed/open, best6, SHA-256
  `73c93111f5606cb218550e9f3b1da88e95cda84095c1af4a21768820896c406d`.

Пути/хеши задаёт локальный JSON, автоматически исходные веса не подбираются.
Процесс API не импортирует ML. Supervisor запускает отдельный Python из
`CG_LOCAL_MODEL_PYTHON`; модели проверяются, загружаются и остаются в perception
worker. CUDA применяется при доступности, иначе CPU с явной отметкой устройства.
Сеть модельного процесса заблокирована, callbacks отключены, autoinstall запрещён.
Существующие training environments и очереди не изменяются.

Main/hands: RGB, letterbox640×640, /255, one-to-many, внешний NMS,
conf0.25/IoU0.7/max_det300 для технических наблюдений. Порог не откалиброван.
Дверь: RGB whole ROI resize224×224 bilinear antialias, /255, без center crop
и повторного softmax. Без отдельного подтверждённого ROI дверь не классифицируется;
ROI стола не является ROI двери. Closed не означает locked.

Frozen PerceptionTrace пока не описывает hand bbox и640; фактические наблюдения
сохраняются отдельным внутренним `inference/observations.json`. Они не выдаются
за совместимый replay trace. В них указаны модели, PTS, coverage и frame detections;
количество уникальных объектов/людей не вычисляется. BoT-SORT/ReID не заявляются:
правило использует пространственные интервалы предмета, не идентичности людей.

## Одно правило и границы

Источник — `ForteBank_Список_нарушений.pdf`, п.5, стр.2 «Хранение личных вещей
в кассовой зоне»; описание — вещь сотрудника на рабочем столе, сотрудник приступает
к работе. `ТЗ.docx` в Downloads/Telegram Desktop относится к другому AI CRM проекту
и не использовался. Исходный `Кейс_ForteBank.docx` в checkout не найден;
API/TЗ изложены в `analysis/case_analysis.md` и замороженных схемах.

Норма из существующего каталога: ПКО, НБРК №231 от29.11.2019, п.12 ч.1:
«Хранение личных вещей, наличных денег и ценностей работников банка осуществляется
вне кассового узла». Полный исходный пункт — `analysis/normative/PKO_NBRK_231_2019_V1900019680.txt`.

Необходимы подтверждённые человеком кассовый узел, поверхность кассира без
клиентской стороны/стульев/прохода и принадлежность вещей сотруднику.
На этой поверхности модель должна устойчиво наблюдать `personal_bag`, рядом —
человека и руку в рабочей зоне/внутри рамки человека. Сумка целиком внутри ROI,
confidence≥0.5, пространственная устойчивость IoU≥0.65, интервал≥2с.
Две секунды — технический debounce; численного срока в п.5 нет. Контекст рук
не доказывает владельца: без отдельного ручного подтверждения правило блокируется.
`outerwear` исключён, поскольку класс не представлен в обучении; collection_bag
не принимается за личную сумку. Это не распознавание действия или личности.

Начало и timecode — первый PTS устойчивой последовательности; событие выдаётся
после накопления интервала, конец — последний подтверждённый sampled PTS.
Удаление/пропуск/сдвиг разрывает интервал; пропуск не трактуется как доказанное
удаление вещи. Доказательства: исходный sampled кадр начала и конца (1–2 JPEG).
Все frames/timestamps из PyAV PTS. Неполный проход/отсутствующий PTS/NaN — failed.

Качество personal_bag слабо проверено (0val, мало train), outerwear не обучен,
руки обучены на публичном домене. **Нет кандидатов → failed/inconclusive с понятным
сообщением, а не no_violation.** Не подтверждённая калибровка/принадлежность/другая
камера также дают failed. Только положительный технический кандидат может пройти
существующий рендер и публикацию; это не подтверждение качества на неизвестном видео.
Остальные нарушения не оцениваются, Qwen не подключён.

## Ручная калибровка

`http://127.0.0.1:8127/local-calibration`: стоп-кадр после поворота, исходный размер,
SHAвидео/PTS и выделение мышью. До нажатия «Подтвердить и сохранить» запись не идёт.
Результат сохраняется атомарно с video ID/SHA, width/height, rotation, framePTS,
ROI и временем подтверждения. ROI привязан только к этому видео; иной ракурс
требует новой проверки. Принадлежность вещей — отдельный необязательный флажок;
его отсутствие сохраняет калибровку поверхности, но блокирует итог правила.
При повторном открытии видны подходящие сохранённые координаты и статус;
все флажки нового подтверждения выключены. Загрузка страницы ничего не сохраняет.
С экрана failed есть переход к настройкам и явное пояснение, что стол/рука рядом
не доказывают принадлежность вещи. Context-кадр может быть в конце события;
его нейтральная подпись — «Кадр контекста».
Маршруты loopback-only, same-origin для POST, no-store и без внешних скриптов.
Изображения не отправляются агенту, телеметрии или сторонним AI.

## Запуск

В PowerShell из ветки с изменениями:

```powershell
.\scripts\start_local_analysis.ps1 `
  -ApiPython '<API-venv>\Scripts\python.exe' `
  -MlPython '<ML-runtime>\Scripts\python.exe' `
  -Config '<local-analysis.json>' -Port 8127
```

JSON содержит `weights.main/hands/door` с path/sha256/name, `calibration_source`,
`calibration_file`, общий `gpu_lock_path`, sample_fps2, deviceauto и rule.min_duration_sec2.
Пример конкретного профиля команды и окружения сохранён в локальном числовом
handoff отчёте; абсолютные пути машины/медиа не коммитятся.

UI сборка: `cd web; pnpm build`; тесты `pnpm test`, `pnpm typecheck`, `pnpm lint`.
Backend: `uv run just check` (с уже настроенным Python3.12 lock environment).
Сквозной тест реальных моделей только по явному opt-in:

```powershell
$env:CG_E2E_REAL_MODELS='1'
$env:CG_LOCAL_TEST_VIDEO='<локальный X-2.mov>'
$env:CG_E2E_NUMERIC_REPORT='<локальный report.json>'
pnpm exec playwright test e2e/local-models.operator.spec.ts --project chrome-desktop
```

Тест выключает screenshots/video/trace и проверяет реальную отправку через UI,
опрос, прогресс и отказ от чистого результата до калибровки. Числовая positive
fixture отдельно проверяет правило → jury/UI → URL доказательств; она не является
ML-оценкой и не используется в рабочем обработчике. Обучающий X-2 подходит только
для проверки соединения компонентов. Качество на независимом наборе не измерено.

Перенос кода на Mac описан в [инструкции](mac_local_analysis_handoff.md).
Архив изменений не включает банковские медиа, калибровки, модели или окружения.
Core ML не подключён; возможный CPU PT-запуск на Mac остаётся непроверенным.
