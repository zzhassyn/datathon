# K4: исполнение backend-стадий

**Цель:** выполнить согласованные стадии K4 через замороженные `StageSet`/`StageJob`, сформировать проверяемый `AnalysisResult` и сохранить промежуточные артефакты.

**Основание:** `scripts/README_BACKEND_HANDOFF.md` §8, `docs/pipeline.md` §§8–13, ADR-0012. Архитектура проекта и публичные контракты сохраняются. Работа выполняется последовательно в `codex/k4-backend-pipeline`.

## Ограничения

- Только локальная обработка, без чтения кадров/видео датасета агентом.
- Никаких новых зависимостей или изменений контрактов; Python 3.12.
- Нормы и шаблоны только из существующего проверенного каталога.
- Неподключённые ML/VLM-стадии не подменяются пустым успешным результатом; startup guards сохраняются.
- Метрики smoke-прогонов не доказывают качество готового сервиса.

## Порядок

- [x] Вердикт (`pipeline/verdict/decide.py`): балл длительности, объединение одного кода, пороги, ограниченное подавление, VLM только понижает. Тесты `tests/unit/verdict/test_decide.py`: границы порогов, раздельные события/треки, неизвестные qid, конфликт ответов, проверка монотонности VLM.
- [x] Описание (`pipeline/legal/describe.py`): факты → шаблон, применимость норм, точные утверждённые правовые формулировки; тесты `tests/unit/legal/test_describe.py` и snapshot.
- [x] Runtime-ресурсы и исполнение runner: валидированные зависимости за существующими портами, явная передача backend/store/plan/config/progress, упорядоченные стадии, границы времени, проверка идентичности трассы, атомарные числовые артефакты. Тесты `tests/unit/pipeline/test_runner.py` на синтетических данных и встроенных StageSet.
- [x] Документация и проверки: unit/contract/API/worker регрессии, ruff, basedpyright, import-linter, дрейф схем. Зафиксировать, какие зависимости K4 ещё не предоставлены ML/VLM.

## Критерии проверки

Чужая трасса, отсутствие evidence, исчерпание срока, ошибка стадии и неподдерживаемый режим должны завершаться ошибкой, а не чистым вердиктом. Объединение кандидатов не повышает исходный балл; ответ VLM не переносится между событиями. Отсутствующий обязательный факт не позволяет безусловно применить правовую норму. Все проверки используют только синтетические числовые входы.

## Журнал

- Создан отдельный managed worktree, установлены зависимости строго по существующему `uv.lock`.
- Уточнение объёма: этот срез реализует backend runner/вердикт/описание. Выпуск весов, perception/evidence adapters, реализация scene/rules и VLM остаются отдельными обязательными частями K4 и не считаются закрытыми.
- Решение: контракты и существующий renderer сохранены. Ресурсы привязываются через наследника StageSet, фабрика действует в контексте spawned worker; никаких резервных режимов.
- Решение: без готового контракта усечения неполный perception-проход завершается ошибкой. Индекс FrameStore обязан соответствовать sampled-потоку; его полноту относительно декодирования обеспечивает будущий ML-адаптер.
- Решение: неподключённые, полностью отключённые и упавшие вердиктные правила не подтверждают чистый ролик. Все включённые пороги задаются явно, VLM scoring не использует предполагаемые значения.
- Ревью отдельным агентом нашло три ошибки (внутреннее покрытие трассы, неявный tau, fallback пропущенного VLM); все воспроизведены и исправлены. Повторное read-only ревью подтвердило исправления, 11 целевых регрессий проверены ревьюером.
- Проверка 18.10.2026: целевой набор — 102 passed; полный backend — 771 passed, 3 skipped, 2 failed. Оба падения уже присутствовали в исходном main: создание symlink без привилегии Windows (WinError 1314), `test_invalid_analysis_never_becomes_clean_or_done[symlink]` и `test_session_guard_and_private_assets`.
- Ruff, форматирование, basedpyright, 7 import-linter contracts, проверка дрейфа 14 схем и `git diff --check` прошли. Полный `uv run --frozen just check` на этой машине не зелёный из-за двух исходных symlink-тестов; frontend-часть рецепта после pytest не выполняется. Новых зависимостей и изменений web/контрактов нет.
- Подготовка merge по запросу человека: два исходных symlink-теста приведены к платформенному поведению проекта — пропуск строго по WinError 1314; остальные ошибки пробрасываются. Проверка session/private assets отделена от проверки symlink и выполняется всегда.

Node/pnpm подготовлены во временном каталоге без изменения системных версий.
