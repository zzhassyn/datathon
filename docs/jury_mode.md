## 1. Что важно для жюри

Из ТЗ и FAQ:
- Жюри загружает видео удалённо по нашей ссылке (FAQ 13). Финальная проверка — 5 и более видео (FAQ 12). Они могут прийти одновременно.
- Лимит — 5 минут на видео. Если сервис недоступен или не вернул результат за 5 минут, видео засчитывается как необработанное (ТЗ §10, FAQ 14).
- FAQ 18: оценка автоматическая по единой схеме; наша трактовка — лишние поля могут сломать разбор, поэтому их нет.
- Финальное видео снято под другим углом (FAQ 4).
- Тестовые видео нельзя использовать для обучения, публиковать или передавать третьим лицам (ТЗ §10).

Наши внутренние цели ([architecture.md](architecture.md), разделы 4 и 9; оценки до замера):
- все задачи жюри — готовы не позже 240 с от прихода запроса (запас 60 с до лимита 300 с); аварийный предел — 250 с (рубеж `perception_hard_stop`, [api.md](api.md), раздел 3.7);
- пачка из 10 видео — каждая задача готова ≤ 300 с от своего POST (цель ≤ 270 с), лишние — по правилам без VLM;
- обычный ролик 15–25 с — финальный результат за 25–35 с; ролик 145 с — за 60–65 с;
- пачка 5 × 145 с — последняя готова за 175–190 с;
- на пике свободно ≥ 3 ГБ памяти.

## 3. curl из ТЗ с мобильной сети

Проверка идёт с другой сети, чем у Mac: Windows-ПК на телефонной точке доступа (мобильные данные), Wi-Fi ПК выключен. Так проверяется настоящий путь жюри: внешний DNS, Cloudflare, туннель.

`<host>` — публичное имя (например `cashguard.<domain>`). `<ключ>` — ключ жюри. Ролик — синтетический из `scripts/make_synthetic_mov.py` или своя съёмка команды. Ролики датасета на Windows-ПК не копируются: там работают агенты (Claude Code, Codex), а видео и кадры живут только на Mac ([training.md](training.md), раздел 5.2). Синтетика проверяет время ответа и форму JSON, но не качество обнаружения.

**Точная команда из ТЗ** (bash, macOS, Git Bash):

```bash
curl -X POST https://<host>/api/v1/analyze \
     -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
```

В PowerShell 5.1 `curl` — это псевдоним `Invoke-WebRequest`. Вызывать `curl.exe`, одной строкой:

```powershell
curl.exe -X POST https://<host>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video_017.mov"
```

Ожидание: HTTP 200 и `{"job_id":"<32 hex-символа>"}`.

**Опрос результата** (только сводка: полный ответ содержит base64-кадры, в терминал его не выводим):

```bash
curl -s https://<host>/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>" | jq '{status,verdict,n:(.violations|length)}'
```

| Состояние | Ответ |
|---|---|
| в работе | `{"job_id":"…","status":"processing","verdict":null,"violations":[]}` |
| готово | ключи ровно по ТЗ §10: `job_id`, `status`=`done`, `verdict` (`violation` или `no_violation`), `violations[]` с `type`, `timecode_sec`, `description`, `evidence_frames[]` (1–3 кадра, `timestamp_sec`, `image_base64` начинается с `/9j/`) |
| ошибка | `{"job_id":"…","status":"failed","verdict":null,"violations":[]}` |

Опрос с ожиданием реализован в `scripts/smoke_jury.sh` (интерфейс зафиксирован в карточке P0-S1-04):

```bash
bash scripts/smoke_jury.sh https://<host> <ключ> <файл.mov>
```

Скрипт пишет полный ответ в `var/smoke/result_<job_id>.json` (в `.gitignore`) и печатает только сводку. Ручной вариант — [api.md](api.md), раздел 3.9.

**Обязательные проверки с мобильной сети:**

| Проверка | Команда | Ожидание |
|---|---|---|
| Жив ли сервис | `curl -s -w '\n%{http_code}\n' https://<host>/health` | `{"status":"ok"}` и 200 |
| Без ключа | `curl -s -o /dev/null -w '%{http_code}\n' -X POST https://<host>/api/v1/analyze -F "file=@video_017.mov"` | 401 |
| Неверный ключ | то же с `-H "X-API-Key: wrong"` | 401 |
| Косая черта в конце | `curl -s -o /dev/null -w '%{http_code}\n' -X POST https://<host>/api/v1/analyze/ -H "X-API-Key: <ключ>" -F "file=@video_017.mov"` | 200, не 307 |
| Неизвестный id | `curl -s -w '\n%{http_code}\n' https://<host>/api/v1/jobs/0123 -H "X-API-Key: <ключ>"` | 404, тело JSON |
| Полный цикл | команда из ТЗ, затем опрос | `done` раньше 240 с, ответ валиден по схеме |
| Интерфейс | открыть `https://<host>/` с телефона, загрузить ролик | статус, вердикт, кадры, норма |
| Загрузки через UI в окне жюри | с одного телефона 6 загрузок через UI подряд за 10 минут, по 3 одновременно (профиль UI «окно жюри» включён) | ни одного 429, все `done` ≤ 300 с |

В Windows-командах вместо `-o /dev/null` писать `-o NUL`.

## 4. Репетиция: 5 параллельных загрузок и отказы

Репетиция проводится дважды до окна (P4, [roadmap.md](roadmap.md)). Результаты записать в журнал: время, что проверяли, итог. Шаги с пометкой «(человек)» выполняет человек: они рвут сеть или сессию агента, требуют входа в систему или касаются ключа.

### 4.1. 5 параллельных загрузок

Основной инструмент — `just jury-sim URL KEY N` ([eval.md](eval.md)). Он отправляет N роликов одновременно, опрашивает каждый раз в 3 с и проверяет каждый ответ по замороженной схеме.

Ролики для `jury-sim` с Windows-ПК — только синтетические (`scripts/make_synthetic_mov.py`): у каждого свой sha256, среди них есть ролики длиной 145 с (параметр длительности — проверить у S1). Синтетика меряет время и форму ответа, но не качество. Реалистичная пачка на роликах датасета запускается только с ноутбука человека, на котором нет агентских сессий; после прогона файлы с него удаляются.

```bash
read -rs KEY                                  # ключ жюри без эха и без записи в историю
uv run just jury-sim https://<host> "$KEY" 5
```

Запускать с Windows-ПК на телефонной точке доступа, через публичный URL (Git Bash; в PowerShell передать ключ из переменной так же, не печатая его в команде).

Критерии прохождения:
- все 5 задач в `done` не позже 240 с от своего POST;
- ни одного ответа 5xx;
- ни одного 429 или 503 на ключ жюри;
- все ответы валидны по схеме.

Затем:
- N=10 (из них ≥ 3 ролика по 145 с) — каждая задача `done` ≤ 300 с от своего POST (цель ≤ 270 с); лишние — `result_level=rules` или `perception_min`; ни одного 5xx и `failed`. Если гейт не пройден, настраиваем уровень `min` и рубеж `perception_hard_stop` в `configs/deadlines.yaml`, а не записываем провал в ограничения;
- один и тот же файл дважды — второй ответ мгновенный (кэш результата).

Важно про кэш: результат кэшируется по `(sha256, pipeline_version, config_hash)`. Повторный прогон тех же 5 роликов покажет время кэша, а не реальной обработки. Для замера времени брать каждый раз новые синтетические ролики (другой sha256) или очищать кэш результатов (раздел 11.3 [runbook_mac.md](runbook_mac.md)).

Ручной вариант без `jury-sim` (bash):

```bash
URL=https://<host>; read -rs KEY
for f in a.mov b.mov c.mov d.mov e.mov; do
  curl -s -X POST "$URL/api/v1/analyze" -H "X-API-Key: $KEY" -F "file=@$f" &
done; wait
```

### 4.2. Внесение отказов

Каждый пункт — во время идущей пачки, если не сказано иное. pid воркеров — из `just status` или `pgrep -fl "cashguard.workers --role"`.

| Отказ | Как | Ожидаемый итог |
|---|---|---|
| Падение perception посреди задачи | `kill -9 <pid perception>` | задача всё равно `done`: вторая попытка на уровне `fast` |
| Падение vlm посреди задачи | `kill -9 <pid vlm>` | уходит предварительный результат (`result_level=rules`, `vlm_crash`) |
| Зависание perception | `kill -STOP <pid perception>` | supervisor убивает его после 60 с без прогресса; задача `done` ≤ 300 с от POST |
| Обрыв сети на 30 с (человек) | отключить сеть Mac на 30 с; агентская сессия на Mac при этом рвётся | туннель переподключается; задачи досчитываются |
| 10 параллельных загрузок | `jury-sim … 10` | нет 5xx; каждая задача `done` ≤ 300 с от своего POST |
| Не видео | загрузить `.txt` | 415 с понятной ошибкой |
| Телефонный ролик HEVC с поворотом | загрузить | обработан; таймкоды и кадры верные |
| Ролик 145 с внутри пачки | добавить в пачку | все в пределах 240 с |
| Перезагрузка (человек) | перезагрузить Mac, войти вручную | агенты поднялись, `/ready` = 200, задачи не потеряны |
| Без интернета, холодный старт (человек) | выключить Wi-Fi и Ethernet → `just services-restart` → дождаться `/ready` = 200 (прогрев всех моделей офлайн) → curl из ТЗ на 3 роликах против `http://127.0.0.1:8000` | все `done`: ни старт процессов, ни обработка не ходят в сеть (гейт релиза, проверка локальности) |
| Резервный адрес | 5 параллельных загрузок через `https://<mac>.<tailnet>.ts.net` | все `done` |

## 5. Чек-листы по времени

Чек-лист заморозки привязан к тегу (Ч+29,5–30, [roadmap.md](roadmap.md), раздел 6). Чек-листы T-2h, T-1h и T-15min отсчитываются от начала окна жюри, когда организаторы его подтвердят (вопрос 1 к организаторам).

### Заморозка (P4-S0-01, Ч+29,5–30)

Заморозка не перезапускает тяжёлые прогоны. Она сверяет, что результаты P4-S3-01 (eval-full, perf, robustness) и P4-S6-02 (jury-sim, Wi-Fi off, Funnel, WebKit) получены на коммите-кандидате тега.

- [ ] S0 ставит тег `jury-v1` на `main`. После этого в код только исправления блокеров через S0.
- [ ] На Mac: `git fetch && git checkout jury-v1`.
- [ ] `uv sync --locked --extra ml --extra mac`.
- [ ] `just build-web` (pnpm build).
- [ ] Сверка sha256 моделей с `configs/models.yaml` (воркеры стартуют, admin status показывает ожидаемые версии).
- [ ] Отчёт `just eval-full` из P4-S3-01 на коммите-кандидате: recall по видео = 1.0; точность записана ([eval.md](eval.md)).
- [ ] Отчёт `just perf` из P4-S3-01 (режим SERVE): этапы в бюджете `configs/perf_budget.yaml`, свободно ≥ 3 ГБ.
- [ ] Отчёт P4-S6-02: тест без интернета с холодным стартом (раздел 4.2, строка «Без интернета»), `jury-sim` N=5 и N=10 через публичный URL с телефонной точки (раздел 4.1).
- [ ] Две репетиции с отказами (раздел 4.2) — проведены или запланированы до T-2h.
- [ ] В `~/.config/cashguard/.env` выставлено `CG_RETENTION_HOURS=0` (очистка выключена) или ≥ 168 на всё окно жюри. После подтверждения организаторов, что проверка закончена, — раздел 6, шаг 3 (ручная очистка).
- [ ] В том же `.env` выставлены лимиты UI режима жюри: `CG_UI_RATE_*` = 30 загрузок за 10 мин на IP, 5 активных на IP, общая очередь UI 20 ([api.md](api.md), раздел 6.1; [runbook_mac.md](runbook_mac.md), раздел 3.6).
- [ ] (человек) `just gen-key`: новые ключи jury и team пишутся прямо в `~/.config/cashguard/.env` (chmod 600), ключ на экран не выводится; перезапуск supervisor, проверка: старые → 401, новые → 200. Агентская сессия этот шаг не выполняет: ключ не должен попасть в её журнал.

- [ ] Для резерва на Windows-ПК подготовлены копии `~/.cloudflared/<UUID>.json` и `config.yml` (хранить вне git, только у команды).
- [ ] Статус актов на adilet не изменился ([legal_sources.md](legal_sources.md), раздел 7).

### Во время окна

Правила:
- Руки прочь от Mac. Нет `git pull`, нет перезапусков, нет обновлений, нет новых приложений.
- Нет обучения, eval, `jury-sim`, Label Studio, браузера на Mac.
- Не открывать результаты задач жюри в интерфейсе и не сохранять их кадры. Исключение — разбор инцидента.
- Вмешиваться только по [runbook_mac.md](runbook_mac.md), раздел 10.

Мониторинг на Mac (только Terminal):

```bash
cd ~/cashguard
while true; do clear; uv run --no-sync just status; sleep 15; done
```

Мониторинг с Windows-ПК (наблюдатель), раз в 30 с, лёгкий запрос без нагрузки на сервис:

```powershell
while ($true) {
  try { $r = Invoke-WebRequest -UseBasicParsing -TimeoutSec 10 https://<host>/health; "$(Get-Date -f HH:mm:ss) $($r.StatusCode)" }
  catch { "$(Get-Date -f HH:mm:ss) FAIL $($_.Exception.Message)" }
  Start-Sleep 30
}
```

Что смотреть в `just status`:

| Показатель | Норма | Если нет |
|---|---|---|
| Воркеры | `idle` или `busy`, свежий `progress_at` | [runbook_mac.md](runbook_mac.md), 10.2 |
| Очередь perception | убывает | наплыв; задачи жюри идут первыми; ждать |
| Свободная память | ≥ 3 ГБ | 10.3 |
| Туннель | готов | 10.4 |
| Последние задачи | `done`, уровни `full`; изредка `rules` | частые `rules` или `fast`/`min` — записать в журнал, не вмешиваться |
| Диск | ≥ 5 ГБ | 10.5 |

## 6. После окна

Сервис держать включённым, пока организаторы не подтвердят, что проверка закончена. Если команда пройдёт в шортлист, интерфейс может понадобиться для демонстрации на питчинге (FAQ 19).

1. (человек) Перевыпустить ключ жюри: `just gen-key` (пишет прямо в `.env`, на экран не выводит), перезапустить supervisor. Старый ключ → 401.
2. Снять метрики прогона для питчинга: тайминги, уровни, деградации из admin status или SQLite (без кадров и без роликов).
3. Удалить каталоги задач жюри: `var/jobs/` (раздел 11 [runbook_mac.md](runbook_mac.md)). Ролики и кадры жюри никуда не копировать (ТЗ §10). Затем вернуть `CG_RETENTION_HOURS=24` и обычный профиль лимитов UI.
4. После окончания события — полная очистка по [runbook_mac.md](runbook_mac.md), раздел 11.3: `var/`, `data/`, `runs/` на Mac и копии на Windows-ПК (FAQ 6).
5. Публикация репозитория (AGPL-3.0) — по решению команды после события, без секретов и данных (открытый вопрос 8).

## 7. Что отправить организаторам (ТЗ §8)

Канал и формат сдачи — как укажут организаторы (проверить). Дедлайн — 12:00 (FAQ 33; дату уточнить).

## 8. Передача ключа

- Ключ жюри — отдельный от ключа команды. Генерация — `just gen-key` (`secrets.token_urlsafe(32)`), запускает человек; ключ пишется прямо в `~/.config/cashguard/.env` и на экран не выводится. Для отправки человек читает его из `.env` сам.
- Передавать только по официальному каналу организаторов. Не в общий чат, не в README, не в git, не на скриншотах.
- Перед отправкой проверить этот же ключ с мобильной сети (раздел 3).
- Ключ передаёт связной. Один раз. Если ключ пришлось сменить — сообщить новый тем же каналом и проверить старый → 401.
- После окна ключ перевыпускается (раздел 6).

Шаблон сообщения:

```text
Команда <название>. Сервис CashGuard.
Интерфейс: https://<host>/
API: POST https://<host>/api/v1/analyze (поле file), GET https://<host>/api/v1/jobs/{job_id}
Ключ жюри (заголовок X-API-Key): <ключ>
Резервный адрес (тот же API и интерфейс): https://<mac>.<tailnet>.ts.net/
Документация: <ссылка на README>
Контакт на время проверки: <имя, телефон>
```

## 9. Что делать, если в окно что-то пошло не так

Подробные шаги — [runbook_mac.md](runbook_mac.md), раздел 10. Здесь — кто что решает.

| Ситуация | Первое действие | Сообщать организаторам? |
|---|---|---|
| Публичный `/health` не 200, локальный 200 | оператор: 10.4 (туннель) | если дольше нескольких минут — да, дать резервный адрес |
| Локальный `/health` не 200 | оператор: 10.1 | если дольше 1–2 минут — да |
| Задача висит в `processing` | задача должна закрыться не позже t0 + 250 с (`perception_hard_stop`); если нет — [runbook_mac.md](runbook_mac.md), 10.2 | нет |
| Свободной памяти < 3 ГБ | оператор: 10.3 | нет |
| Mac уснул или перезагрузился | оператор: войти, 10.6 | да, если был простой |
| Mac мёртв | 10.9: резерв на Windows только после отключения коннектора Mac | да, сразу |
| Жюри пишет про 401 | связной сверяет ключ; 10.7 | ответ по их каналу |

Журнал инцидентов: время (местное), что увидели, что сделали, итог. Он нужен для разбора и для питчинга.
