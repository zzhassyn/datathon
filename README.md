# CashGuard — нарушения кассовой дисциплины по видео

> Локальный анализ видео кассы: признаки нарушения → таймкод PTS → кадры-доказательства → описание и норма РК.

CashGuard — локальный AI-сервис для ForteBank Datathon 26. Пользователь загружает видеозапись кассы (`.mov` или `.mp4`). Сервис:
- отвечает, есть ли видимые признаки возможного нарушения (`violation` или `no_violation`);
- для каждого нарушения показывает тип, таймкод, 1–3 кадра-доказательства и описание того, что видно;
- указывает правило и нормативный акт Республики Казахстан (название, пункт).

Обработка видео выполняется локально, без облачных AI-вызовов и распознавания лиц. Результат помогает человеку проверить событие. Основной профиль использует три правила; адаптивный фильтр посетителей включён по умолчанию. Качество последней версии на реальных видео ещё не измерено.

## Быстрый запуск без моделей

Нужны Python 3.12, uv, Node.js 24.22.0 и pnpm 10.34.7. Установка backend- и frontend-зависимостей и запуск разработки:

```bash
uv run just setup
uv run just build-web
uv run just dev 8137
```

Откройте [http://127.0.0.1:8137](http://127.0.0.1:8137). Этот режим использует `stub`: он проверяет интерфейс, API и очередь, но не анализирует видео моделями. Для распознавания нужен [полный запуск](#как-запустить-полный-анализ) с локальными весами.

## Проверка через API (ТЗ, раздел 10)

Загрузка видео:

```bash
curl -X POST "<URL>/api/v1/analyze" \
     -H "X-API-Key: <API_KEY>" -F "file=@video_017.mov"
# → {"job_id": "<32 hex-символа>"}
```

Статус и результат (опрашивать, пока `status` не станет `done` или `failed`, например раз в 3 с):

```bash
curl "<URL>/api/v1/jobs/<job_id>" -H "X-API-Key: <API_KEY>" -o result.json
```

| `status` | Ответ |
|---|---|
| `processing` | `{"job_id": "...", "status": "processing", "verdict": null, "violations": []}` |
| `done` | ровно поля из ТЗ §10: `verdict` = `violation` или `no_violation`; `violations[]` с `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG в base64) |
| `failed` | `{"job_id": "...", "status": "failed", "verdict": null, "violations": []}` — файл не читается как видео или анализ упал |

Ответ сохраняется в файл, поскольку содержит JPEG в base64. Для сквозной проверки предусмотрен [scripts/smoke_jury.sh](scripts/smoke_jury.sh). Сокращённый пример `done`:

```json
{
  "job_id": "<job_id>",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Ценности оставлены без присмотра при уходе",
      "timecode_sec": 18.0,
      "description": "<что видно на кадре>. Основание: <пункт, акт>.",
      "evidence_frames": [{ "timestamp_sec": 18.0, "image_base64": "/9j/..." }]
    }
  ]
}
```

Гарантии ответа:
- в ответе нет полей сверх ТЗ §10 (схема заморожена: [jury_job.schema.json](src/cashguard/contracts/schemas/jury_job.schema.json)); нарушений не больше 5;
- `evidence_frames[0].timestamp_sec` совпадает с `timecode_sec`; `image_base64` — JPEG без префикса `data:`; таймкоды берутся из PTS кадров;
- одинаковые активные задачи объединяются по sha256 файла, версии пайплайна и конфигурации; готовые ответы кэшируются только для уровня `full`. Текущий числовой обработчик публикует уровень `rules`, поэтому повторный завершённый анализ может запуститься заново.

| Код | Когда |
|---|---|
| 401 | нет ключа или ключ неверный |
| 404 | неизвестный или некорректный `job_id` |
| 413 | файл больше 100 МБ |
| 415 | не QuickTime/MP4 или контейнер не читается |
| 422 | нет поля `file` |
| 507 | на сервере мало места на диске |

## Веб-интерфейс

1. Откройте адрес из таблицы выше и перетащите видео `.mov` или `.mp4` до 100 МБ.
2. Видны этапы обработки; итог — «Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений».
3. В карточке нарушения — тип, таймкод, описание, норма и кадры-доказательства. Маркеры на шкале видео переводят плеер к событию.
4. Страница «Типы нарушений и нормы» — `<URL>/?view=types`.

Подробно: [docs/ui.md](docs/ui.md).

## Что проверяет сервис сейчас

В приведённом ниже профиле включены **3 типа нарушений** (`temporal_rules.codes`); фактический набор задаёт локальная конфигурация:

| Код | Тип для жюри (`type`) | Когда срабатывает | Норма |
|---|---|---|---|
| `VALUABLES_LEFT` | Ценности оставлены без присмотра при уходе | подтверждён выход кассира; наличные и отсутствие людей наблюдаются на всём минимальном интервале | ПКО п. 20 ч. 2, п. 22, п. 80 (прямая) |
| `THIRD_PERSON_DURING_SERVICE` | Постороннее лицо / второй клиент во время операции | у стола ≥ 2 посетителей не меньше 2 с (порог — оценка); исключаются кассир, дубли и фон по адаптивному размеру | ПОП п. 8, п. 16 пп. 1) (косвенная) |
| `SAFE_OPEN` | Сейф оставлен открытым | логика есть, но детектор почти не выдаёт класс `safe_open` (обучен на 2 кадрах), поэтому на практике не срабатывает | ПКО п. 20 ч. 2 (косвенная) |

Остальные типы каталога (всего 26 кодов, [docs/violation_catalog.md](docs/violation_catalog.md)) показаны в интерфейсе, но **не оцениваются этим профилем**. В режиме `auto_zones` отсутствие кандидатов даёт `no_violation` только в рамках выбранных правил; основание записывается в `technical_scope.json`. Если стол не найден, этот режим также возвращает `no_violation` с внутренней причиной `scene_not_recognized`. Если стол найден, но кассира определить нельзя или лучшие оценки равны, задача завершается `failed`. При ручной калибровке отсутствие кандидатов пока блокирует чистый вердикт.

### Адаптивный фильтр посетителей

`THIRD_PERSON_DURING_SERVICE` использует `person_size_mode="adaptive"`, в том числе когда настройка отсутствует в JSON. Для каждого PTS фильтр оценивает высоту по медианам устойчивых участков треков, наблюдаемых в этот момент: каждый трек получает один голос независимо от длительности. Поздние посетители не меняют порог раннего события, даже если между ними постоянно виден фон. Это позволяет учитывать узкие рамки посетителей и исключать низкий фон в синтетических сценариях.

| Режим | Поведение |
|---|---|
| `adaptive` — по умолчанию | относительный порог высоты; при недостатке уверенных наблюдений автоматически используется прежний порог площади |
| `fixed` — задаётся явно | прежний порог площади; нужен для сравнения и возврата к прежней фильтрации размера |

Настройка действует только на это правило. Все люди сохраняются в общей сцене и учитываются при проверке отсутствия присмотра. Пороги — **оценка**; рост precision/recall на видео не подтверждён. Формула, условия fallback и источник идеи: [docs/pipeline.md](docs/pipeline.md#устойчивость-числовых-правил).

### Исправленные причины пропусков

- Дубли одного трека в кадре больше не стирают движение кассира к выходу. Поздний разрыв наблюдений не отменяет уже подтверждённое событие; отсутствие после разрыва снова считается неизвестным.
- Режим выхода через край кадра работает без найденной двери. Для строгого выхода дверь и направленное движение по-прежнему обязательны.
- Ручная калибровка передаёт найденного кассира и настроенный `scene.max_observation_gap_sec` в правило посетителей. Рамка кассира берётся из его наблюдений, а не из всей зоны рабочего места.
- Отброшенный дубль не лишает подходящий трек временной поддержки. Точные границы длительности и разрывов устойчивы к округлению PTS; допуск не заменяет пропущенный кадр.
- Правило посетителей подключено к общему реестру для `PerceptionTrace`. Включённое, но отсутствующее правило теперь завершает анализ ошибкой, а не молча пропускается.

Эти исправления подтверждены синтетическими регрессиями. Они не добавляют отсутствующие ML-наблюдения: открытый сейф, передача денег, работа с дверью и остальные типы требуют отдельной проверки моделей, зон и правил. Текущий охват по умолчанию остаётся прежним.

Источник — [отчёт сессии](docs/session_report_20261018.md). Числа ниже описывают ту версию и не являются оценкой текущего `main`.

| Метрика | Значение |
|---|---|
| Верные срабатывания | 3 из 20 роликов с нарушением: Х-26 (18,0 с; разметка 9 с), Х-18 (17,0 с; разметка 20 с), Х-30 (13,0 с, совпадает с разметкой; наш тип «второй клиент», в разметке «посторонний») |
| Ложные срабатывания | 0 из 20 чистых роликов |
| Пропуски | 17 из 20 роликов с нарушением |
| Время через API | медиана ≈ 18 с, максимум ≈ 105 с (ролик 142 с), по округлённому отчёту; лимит 300 с не превышен ни разу |

Сервис настроен на точность: лучше пропустить нарушение, чем выдать ложное. Причины пропусков:
- Х-20 (сейф открыт): детектор на всех кадрах видит `safe_closed` с уверенностью ≥ 0,95; `safe_open` обучен на 2 кадрах (AP50 0,08). Нужны данные, а не правило.
- Х-4, Х-38 (деньги предыдущего клиента): нужно событие передачи денег, оно не извлекается.
- Х-32, Х-33 (дверь не закрыта): классификатор двери обучен, но требует отдельной зоны двери на кадре; в автоматическом режиме не подключён.
- Х-15 (инкассаторская сумка без наличных): правило намеренно не выдаёт вердикт, для нормы нужен внутренний регламент банка.
- Х-24, Х-11, Х-28, Х-22, Х-40, Х-46, Х-1, Х-2, Х-13, Х-34, Х-44: правила для этих типов не реализованы или детектор не даёт нужного сигнала.

Это метрики на тех же роликах, из которых брали кадры для обучения детектора; на новых видео точность не измерена. В историческом отчёте использовано разбиение 20/20, в текущей канонической разметке — 21/19 ([docs/eval.md](docs/eval.md)); показатели не пересчитывались без исходных предсказаний. Для повторной оценки новых правил нужны числовые replay-трассы, которых в этой проверке нет.

## Как устроено

```
жюри / браузер ──HTTPS──► Cloudflare quick tunnel ──► api (FastAPI, uvicorn, без ML)
                                                       │ видео → var/jobs/<id>/, задача → SQLite (WAL)
                                                       ▼
                         worker: PyAV (кадры по PTS, 2 кадра/с)
                         → YOLO26s main (14 классов) + YOLO26s hands, PyTorch на CPU
                         → BoT-SORT без ReID (треки людей)
                         → автозоны: стол, дверь, сейф, место кассира по медианам детекций
                         → история сцены → 3 правила → описание и норма из каталога
                         → кадры-доказательства по PTS
                                                       ▼
                               ответ по схеме ТЗ §10 + результат для интерфейса
```

- Процессы `api` и `worker` запускает супервизор `cashguard up`. Процесс API не импортирует ML (проверяет import-linter).
- Задача сохраняется на диск и в SQLite до ответа 200, поэтому перезапуск процесса её не теряет.
- В режиме `auto_zones` зоны строятся по найденным предметам. Для кассира нужны реальные перекрытия стола в трёх разных PTS (порог — оценка); дубли и долгий фон вне стола не добавляют веса. Место кассира определяется только по наблюдениям у стола. Эти зоны — автоматическая оценка, человек их не подтверждает.
- Лица не распознаются (FAQ 29): роли «кассир», «клиент», «посторонний» определяются по зонам и поведению.
- Детектор сам по себе нарушение не выдаёт: тип и таймкод выдают правила, описание и норма берутся из каталога `configs/catalog/<CODE>.yaml`.

Код: сцена — [src/cashguard/pipeline/scene/](src/cashguard/pipeline/scene/) (`temporal.py`, `auto_zones.py`), правила — [src/cashguard/pipeline/rules/](src/cashguard/pipeline/rules/), сборка результата — [windows_analysis.py](src/cashguard/pipeline/windows_analysis.py). Подробно о режиме: [docs/temporal_workflow.md](docs/temporal_workflow.md).

Core ML-версии всех трёх моделей экспортированы и проверены на Mac (детектор: 10,6 мс на кадр против 211 мс в PyTorch), но в сервис не подключены: строгое совпадение ответов с PyTorch для детекторов не прошло. Скорости на CPU при 2 кадрах/с хватает для лимита 300 с.

### Эксперимент: дообучение Qwen3.5-4B (в сервисе не используется)

Проверяли, может ли VLM подтверждать кандидатов по кадрам. QLoRA (NF4, r=8) на NVIDIA T4, 202 примера для обучения и 50 для проверки; метки предварительные, сделаны AI, человеком не проверены.

| Модель | С кадрами | Без кадров |
|---|---|---|

После дообучения ответ зависит от кадров, а не только от текста вопроса. Это совпадение с AI-метками, а не измеренная точность, поэтому адаптер в сервис не подключён; перенос в MLX на Mac не проверялся. В ответе жюри VLM не участвует.

## Как запустить полный анализ

**Хост исторического запуска:** MacBook Pro M2 Pro, 16 ГБ, macOS. Нужны локальные веса, Python 3.12, [uv](https://docs.astral.sh/uv/), Node.js 24.22.0 и pnpm 10.34.7. Команды ниже — для Bash/zsh.

1. Окружения:
   ```bash
   uv run just setup
   uv run just build-web
   ```
   Для модельного процесса нужно отдельное окружение с extra `ml`; закреплённые зависимости — в [pyproject.toml](pyproject.toml) и `uv.lock`. Путь к его Python передаётся в `CG_LOCAL_MODEL_PYTHON`. Проверка этой версии на Mac ещё не выполнена.
2. Ключи (пишутся в `~/.config/cashguard/.env` с правами 600, на экран не выводятся):
   ```bash
   uv run just gen-key
   ```
3. Скопируйте [configs/local_analysis.temporal.example.json](configs/local_analysis.temporal.example.json), задайте абсолютные пути и sha256 локальных весов. Замените блок `temporal_rules`, сохранив остальные поля JSON:
   ```json
   {
     "temporal_rules": {
       "enabled": true,
       "auto_zones": true,
       "codes": ["VALUABLES_LEFT", "SAFE_OPEN", "THIRD_PERSON_DURING_SERVICE"],
       "min_duration_sec": 2,
       "person_size_mode": "adaptive"
     }
   }
   ```
   Для прежней фильтрации размера укажите `"person_size_mode": "fixed"`. Особенности ручной калибровки и публикации описаны в [docs/temporal_workflow.md](docs/temporal_workflow.md).
4. Запуск (замените абсолютные пути на свои):
   ```bash
   CG_PIPELINE_MODE=full CG_VISION_BACKEND=torch CG_VLM_ENABLED=false \
   CG_PIPELINE_VERSION=numeric-rules-v4 \
   CG_LOCAL_MODEL_PYTHON="/absolute/path/.venv-model/bin/python" \
   CG_LOCAL_ANALYSIS_CONFIG="/absolute/path/local_analysis.json" \
   CG_WEB_DIST="$PWD/web/dist" CG_DATA_DIR="$PWD/var" CG_UI_RATE_PROFILE=jury \
   HF_HUB_OFFLINE=1 YOLO_OFFLINE=1 PYTHONPATH=src \
   uv run python -m cashguard.cli up --profile prod --port 8137
   ```
5. Публичный адрес:
   ```bash
   cloudflared tunnel --url http://127.0.0.1:8137 --no-autoupdate
   ```
6. Проверка: `/ready` возвращает 200, затем curl из раздела «Проверка через API».

При обновлении правил меняйте `CG_PIPELINE_VERSION` для API и воркеров и перезапускайте сервис: версия участвует в идентификации задач и кэша. Изменения локального JSON также учитываются в отпечатке конфигурации.

После загрузки весов интернет для обработки видео не нужен (ТЗ, раздел 7): модельный процесс работает с `HF_HUB_OFFLINE=1` и `YOLO_OFFLINE=1`, автоустановка пакетов и сетевые вызовы отключены.

## Проверки разработки

```bash
uv run just check
```

Команда запускает Ruff, basedpyright, import-linter, pytest без Mac/slow-тестов, Biome, TypeScript, Vitest и проверку дрейфа схем. Регрессии фильтра проверяют режим по умолчанию, явный `fixed`, fallback, масштаб, дубли и разрывы наблюдений. Синтетические тесты проверяют логику; измерение precision/recall требует реальных числовых трасс и разметки ([методика оценки](docs/eval.md)).

Последний полный прогон этой версии на Windows: **933 Python-теста и 36 web-тестов прошли**, линтеры, типы, импорты и схемы проверены. Шесть Python-тестов пропущены: нет Torch, прав на symlink и POSIX-сигнала SIGSTOP. Mac-инференс и реальные видео в этот прогон не входили.

## Ограничения

- Оценивается 3 типа из 26. `no_violation` означает «по этим трём правилам ничего не найдено», а не «нарушений нет».
- Исторический прогон обнаружил 3 из 20 нарушений. Для нынешних правил, новых видео и других ракурсов качество не измерено.
- Зоны строятся автоматически по найденным предметам. На новой планировке они могут определиться неверно; если стол не найден, правила не применяются.
- Выход кассира засчитывается по ослабленному критерию: трек заканчивается у двери или края кадра, и до конца ролика в комнате никого нет. Уверенность такого события 0,55.
- Кадры берутся 2 раза в секунду: короткое событие между кадрами можно пропустить.
- Нормы для `THIRD_PERSON_DURING_SERVICE` и `SAFE_OPEN` косвенные.
- Сервис работает на одном Mac через quick tunnel: при перезапуске туннеля меняется адрес, резервного адреса нет.

Полный перечень: [docs/limitations.md](docs/limitations.md).

## Данные и локальность

- Видео жюри не используются для обучения. Папки задач удаляются через 24 часа (`CG_RETENTION_HOURS`).
- Данные хакатона (видео, кадры, разметка) не хранятся в git и не передаются внешним сервисам (FAQ 6).
- Модели загружаются из локальных файлов с проверкой sha256. Туннель только передаёт трафик, обработка идёт на нашем Mac.
- FAQ 35: облачных API и готовых решений нет; только open-source модели и библиотеки (оговорка про AGPL — раздел «Лицензия»). Дообучение Qwen шло на арендованной GPU, но этот адаптер в сервисе не используется.

## Лицензия

- Сервис использует Ultralytics YOLO26 под AGPL-3.0; организаторы подтвердили, что YOLO использовать можно (17.10.2026).
- Сервис доступен по сети, поэтому его код распространяется под AGPL-3.0 ([LICENSE](LICENSE)).
- Для коммерческого использования в банке нужно либо открыть код, либо купить Enterprise-лицензию Ultralytics. Альтернатива — детектор RF-DETR (Apache-2.0).
- Колёса PyAV для macOS включают FFmpeg (LGPL) и компоненты x264/x265 (GPL).
