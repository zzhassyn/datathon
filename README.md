# CashGuard — нарушения кассовой дисциплины по видео

> **Назначение:** точка входа для жюри и проверяющих по ТЗ, раздел 8: адреса, ключ, запуск, архитектура, модели, ссылки на типы нарушений, нормы и ограничения.
> **Владелец:** S0 (интегратор) · **Статус:** черновик v1, 17.10.2026. Значения в `<...>` заполняются перед сдачей.

CashGuard — локальный AI-сервис для ForteBank Datathon 26. Пользователь загружает видеозапись кассы (`.mov`). Сервис:
- отвечает, есть ли видимые признаки возможного нарушения;
- для каждого нарушения показывает тип, таймкод, 1–3 кадра-доказательства и описание того, что видно;
- указывает правило и нормативный акт Республики Казахстан (название, пункт).

Все модели работают на нашем сервере. Облачные AI-сервисы не используются. Результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение (ТЗ, раздел 7).

## Проверка через API (ТЗ, раздел 10)

Загрузка видео:

```bash
curl -X POST <PUBLIC_URL>/api/v1/analyze \
     -H "X-API-Key: <API_KEY>" -F "file=@video_017.mov"
# → {"job_id": "<32 hex-символа>"}
```

Статус и результат (опрашивать, пока `status` не станет `done` или `failed`; например, раз в 3 с):

```bash
curl <PUBLIC_URL>/api/v1/jobs/<job_id> -H "X-API-Key: <API_KEY>"
```

| `status` | Ответ |
|---|---|
| `processing` | `{"job_id": "...", "status": "processing", "verdict": null, "violations": []}` |
| `done` | ровно поля из ТЗ §10: `verdict` = `violation` или `no_violation`; `violations[]` с `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG в base64) |
| `failed` | `{"job_id": "...", "status": "failed", "verdict": null, "violations": []}` — файл не читается как видео (`UNSUPPORTED_VIDEO`) или анализ дважды упал до предварительного результата (`PIPELINE_CRASH`) |

Пример ответа `done`:

```json
{
  "job_id": "<job_id>",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "<название типа из каталога>",
      "timecode_sec": 14.0,
      "description": "<что видно на кадре>. Может свидетельствовать о несоблюдении <пункт, акт>.",
      "evidence_frames": [{ "timestamp_sec": 14.0, "image_base64": "/9j/..." }]
    }
  ]
}
```

Гарантии ответа:
- в ответе нет полей сверх ТЗ §10; нарушений не больше 5, они отсортированы по времени;
- `evidence_frames[0].timestamp_sec` совпадает с `timecode_sec`; `image_base64` — JPEG без префикса `data:`;
- сроки считаются от прихода запроса: сервис рассчитан выдать результат не позже чем через 240 с (лимит жюри — 300 с). При нехватке времени отдаётся результат по правилам без этапа VLM;
- повторная загрузка того же файла отвечает из кэша.

| Код | Когда |
|---|---|
| 401 | нет ключа или ключ неверный; тело запроса не читается |
| 404 | неизвестный или некорректный `job_id` |
| 413 | файл больше 100 МБ |
| 415 | не QuickTime/MP4 или контейнер не читается |
| 422 | нет поля `file` |
| 507 | на сервере мало места на диске |

Подробно: [docs/api.md](docs/api.md).

## Как пользоваться веб-интерфейсом

1. Откройте `<PUBLIC_URL>/` и выберите видео `.mov` или `.mp4` до 100 МБ. Видно процент загрузки, скорость и оставшееся время; видео сразу можно смотреть.
2. После загрузки идут этапы: очередь → проверка файла → распознавание → правила → кадры-доказательства → проверка VLM.
3. Предварительные нарушения появляются, как только готов результат по правилам (метка «Предварительно»). Затем их уточняет VLM.
4. Итог: «Нарушение не обнаружено» или «Обнаружены признаки возможных нарушений». В карточке нарушения — тип, таймкод, описание, норма с цитатой и ссылкой на adilet.zan.kz, кадры (увеличиваются по клику).
5. Маркеры на шкале видео переводят плеер за 2 с до события.
6. Блок «Наблюдения (не влияют на вердикт)» показывает то, что стоит проверить человеку, но не считается нарушением.
7. Страница «Типы нарушений и нормы» — `<PUBLIC_URL>/?view=types`.

Подробно: [docs/ui.md](docs/ui.md).

## Как запустить

Команды `just` появятся в P0 (см. [docs/roadmap.md](docs/roadmap.md)). Все запускаются как `uv run just <recipe>`.

**Боевой хост — MacBook Pro M2 Pro, 16 ГБ, macOS ≥ 14 (рекомендуется 15).** Репозиторий лежит в `~/cashguard`. Порядок:
1. `uv sync --locked --extra ml --extra mac` и сборка веба `uv run just build-web`.
2. Загрузка весов с закреплёнными ревизиями (`training/download_models.sh`) и проверка sha256 по `configs/models.yaml`.
3. Ключи: `uv run just gen-key` → `~/.config/cashguard/.env` (права 600).
4. Сервисы: `uv run just services-install`, затем `uv run just mode serve`. Это LaunchAgents для супервизора, туннеля и `caffeinate`.
5. Проверка: `<PUBLIC_URL>/ready` возвращает 200, затем curl из раздела выше.

Пошагово: [docs/runbook_mac.md](docs/runbook_mac.md), чек-лист дня проверки — [docs/jury_mode.md](docs/jury_mode.md).

**Разработка (Windows, Linux):** `uv run just setup`, затем `uv run just dev`. Модели не нужны: пайплайн работает в режиме `stub` или `replay`.

**Linux с GPU (контур банка):** `deploy/linux/Dockerfile.cuda` и `deploy/linux/compose.yaml` — те же код, lock-файл и три процесса; модели монтируются только для чтения.

После загрузки весов интернет для обработки видео не нужен (ТЗ, раздел 7). Перед сдачей проверяется холодный старт без сети: сеть выключена → `uv run just services-restart` → `/ready` 200 (прогрев всех моделей) → curl из ТЗ на 3 видео → `done`.

## Архитектура

```
жюри / браузер ──HTTPS──► Cloudflare Tunnel ──► uvicorn 127.0.0.1:8000 (api, без ML)
                                                    │  видео → var/jobs/<id>/, задача → SQLite (WAL)
                                                    ▼
             perception worker (Neural Engine + CPU)          vlm worker (GPU)
             PyAV → YOLO26 detect/pose/cls + BoT-SORT          Qwen3.5-4B (MLX)
             → сцена → правила → предварительный результат ──► проверка кандидатов
                                                    │          (только понижает балл)
                                                    ▼
                         jury.json (по схеме ТЗ §10) + ui_result.json
```

- Три процесса под одним супервизором `cashguard up`: `api`, `perception`, `vlm`. Пока VLM проверяет видео N на GPU, распознавание видео N+1 идёт на Neural Engine.
- Задача сохраняется на диск и в SQLite до ответа 200, поэтому перезапуск процесса её не теряет.
- Сразу после распознавания записывается полный результат по правилам. VLM его только уточняет. Если VLM не успевает или падает, уходит результат по правилам.
- Таймкоды берутся из PTS кадров. Кадр-доказательство — это ровно тот кадр, по которому принято решение.
- Типичный ролик 15–25 с: предварительный результат за 7–10 с, итоговый за 25–35 с после загрузки. Ролик 145 с — итог за 60–65 с. Это оценка, её заменит замер `scripts/bench_mac.py`.

Подробно: [docs/architecture.md](docs/architecture.md), [docs/pipeline.md](docs/pipeline.md), решения — [docs/adr/](docs/adr/).

## Подход и модели

Большинство нарушений — это пропущенный обязательный шаг или неверное состояние предмета. Поэтому решение гибридное: модели находят людей, предметы и состояния, а тип и таймкод выдают правила по процедурам. VLM проверяет кандидатов и может только понизить их балл.

| Роль | Модель | Где работает | Обучали? | Лицензия |
|---|---|---|---|---|
| Люди и предметы, 14 классов | YOLO26l detect, `imgsz` 864, Core ML 864×480 и 480×864 | Neural Engine | да, на кадрах датасета | AGPL-3.0 |
| Руки (передача денег, стакан, телефон) | YOLO26l-pose | Neural Engine | нет | AGPL-3.0 |
| Мелкие состояния: экран, ключ в замке, дверь | YOLO26s-cls × 3, 224 | Neural Engine | да | AGPL-3.0 |
| Треки людей | BoT-SORT без ReID по внешности | CPU | нет | AGPL-3.0 |
| Проверка кандидатов | Qwen3.5-4B, mlx-community 8-bit (запасные 6-bit и 4-bit) | GPU (MLX) | нет | Apache-2.0 |
| Предразметка (только обучение, не в сервисе) | YOLO26x COCO + Grounding DINO base | — | нет | AGPL-3.0 / Apache-2.0 (проверить карточку модели) |

Лица не распознаются (FAQ 29): роли «кассир», «клиент», «инкассатор», «посторонний» определяются по зонам и поведению. Обучение: [docs/training.md](docs/training.md), [training/README.md](training/README.md).

## Типы нарушений

- **Влияют на вердикт:** 17 типов из обучающих роликов и 8 видимых типов из списка команды (телефон у кассира, уход до конца обслуживания и др.). Отдельный код — прочее видимое нарушение, найденное VLM: в вердикт идёт только при подтверждении треками и выше высокого порога (политика уточняется, см. [docs/roadmap.md](docs/roadmap.md)).
- **Сигналы (13):** показываются проверяющему в интерфейсе, на вердикт не влияют и в ответ API не попадают.
- **Не детектируются:** события, которые камера не видит (проводки, акты, журналы), и детали, для которых нужна камера крупного плана.

Полный перечень с описаниями и таймкодами: [docs/violation_catalog.md](docs/violation_catalog.md).

## Ограничения

Главное:
- Сервис оценивает только то, что видно в кадре. Корректность проводок, сверок и документов он не утверждает.
- Финальное видео снято под другим углом. Зоны строятся по найденным предметам, но точность на новой планировке может упасть.
- Новые типы нарушений ловит только общий проход VLM. По умолчанию его находки — сигналы, поэтому новый тип можно пропустить.
- Часть норм применяется косвенно. У «еды и напитков» прямой нормы нет. Трактовка «пропуска проверки подлинности» спорна (ПКО п. 41).
- Все цифры скорости и памяти — оценки до замера на Mac.
- Сервис работает на одном Mac. Резерв — второй адрес туннеля и Docker-образ без VLM.

Полный перечень и известные ошибки: [docs/limitations.md](docs/limitations.md).

## Данные и локальность

- Видео жюри не используются для обучения и не хранятся: исходный файл удаляется после распознавания, папка задачи — через 24 часа. В окне жюри автоматическая очистка выключена, чтобы результаты можно было запросить повторно; после окна папки удаляются вручную ([docs/jury_mode.md](docs/jury_mode.md), раздел 6).
- Данные хакатона (видео, кадры, разметка) не хранятся в git и не передаются внешним сервисам (FAQ 6).
- Модели загружаются из локальных файлов с проверкой sha256. Туннель только передаёт трафик, обработка идёт на нашем Mac.
- FAQ 35 (дисквалификация за облачные решения по API и готовые решения): облачных API и готовых решений нет; только open-source модели и библиотеки с лицензией, разрешающей коммерческое использование (FAQ 24; оговорка про AGPL — раздел «Лицензия»).

## Лицензия

- Сервис использует Ultralytics YOLO26 под AGPL-3.0. Организаторы подтвердили, что YOLO использовать можно (17.10.2026): `<ссылка на скриншот ответа>`.
- Сервис доступен по сети, поэтому его исходный код публикуется под AGPL-3.0. Файл `LICENSE` добавляется в P0.
- Для коммерческого использования в банке нужно либо открыть код, либо купить Enterprise-лицензию Ultralytics. Альтернативный путь — детектор RF-DETR (Apache-2.0).
- Колёса PyAV для macOS включают FFmpeg (LGPL) и компоненты x264/x265 (GPL).
- Веса Qwen3.5-4B — Apache-2.0. У репозиториев mlx-community нет карточки, поэтому происхождение записано в манифесте моделей.
