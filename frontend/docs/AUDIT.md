# Аудит для frontend MVP

Дата: 17 октября 2026 года. Исходная точка репозитория `zzhassyn/datathon`: коммит `74c6716` (`init`).

## Что было в репозитории

В исходной версии присутствовал каталог `analysis/`: `case_analysis.md`, `detection_design.md`, `labels_typed.csv` и сохранённые тексты нормативных документов в `normative/`. Это исследования кейса, предварительная типизация и предложение архитектуры.

Исполняемый backend, HTTP-сервер, AI-конвейер, веса модели, готовые API endpoints и frontend в исходной версии не найдены. Упоминания YOLO/Qwen, оценки памяти и времени в документах не подтверждают реализацию или измеренную производительность. Frontend добавлен отдельным каталогом `frontend/`; исходные исследовательские материалы сохранены.

## На какие материалы опирается MVP

- Техническое задание и FAQ в `Кейс_ForteBank.docx` из материалов проекта.
- Официальная таблица `open_labels.xlsx` и локальные видеоматериалы; реальные записи не включаются в публичные frontend-ресурсы.
- Командные PDF/XLSX и материалы предыдущих обсуждений в проекте Datathon.
- Существующие `analysis/case_analysis.md`, `analysis/detection_design.md`, `analysis/labels_typed.csv`, `analysis/normative/`.

Официальная разметка описывает имя файла, бинарный статус и таймкод. Она не предоставляет готовые классы детектора, рамки или confidence. В командных PDF и CSV есть разные трактовки отдельных событий. Поэтому UI использует предварительные категории, а демособытия отдельно обозначены как сценарные. Название нарушения из командной таблицы не считается подтверждённой юридической квалификацией.

## Требования, влияющие на интерфейс

| Требование | Решение в MVP |
|---|---|
| Локальная обработка видео и кадров | В mock файл остаётся в браузере; HTTP-клиент ограничен loopback, перенаправления запрещены |
| Не использовать идентификацию, биометрию и звук | Таких функций в frontend нет; встроенная запись без звука |
| Результат максимум за 300 секунд | Клиент прекращает ожидание; фактическую скорость backend ещё нужно измерить |
| `violation` / `no_violation` и подробности события | Проверяется контракт ответа, 1–3 JPEG, описание и таймкод |
| API из ТЗ | `POST /api/v1/analyze` → `job_id`, `GET /api/v1/jobs/{job_id}`, заголовок `X-API-Key` |
| Проверка человеком | Отдельные статусы «ожидает», «подтверждено», «отклонено» |
| Объяснимость без выдуманных данных | Confidence, правило и рамки показываются только при наличии; иначе явное сообщение |

Максимум ожидания в UI не является замером end-to-end производительности. Перед отправкой результата жюри нужно проверить время от отправки видео до готового ответа, включая передачу и очередь, на целевом MacBook Pro M2 Pro 16 ГБ.

## Обоснованные временные решения

- React + TypeScript + Vite: существующего frontend-стека не было; отдельная директория сохраняет независимость от будущей модели и backend.
- По умолчанию включён mock с вручную заданными событиями и синтетической локальной записью. Он демонстрирует взаимодействие, не качество AI и не содержимое видео пользователя.
- Original / AI Analysis — один плеер с переключаемым слоем аннотаций. При отсутствии координат рамки не синтезируются. Отдельного обработанного видео нет.
- История и решения человека сохраняются в браузере. Исходные видео, байты кадров и ключ API не сохраняются постоянно. Текстовые результаты сохраняются и могут быть чувствительными.
- Настройка локального API не подтверждает его доступность. Реальная интеграция требует запуска backend и прохождения полного сценария.
- Распознавание и превью разделены: браузер может не поддержать кодек MOV, но это не запрещает отправить файл backend.

## Что осталось для команды

Согласовать каталог событий и правила, реализовать API и локальный AI-конвейер, подтвердить качество и скорость на контрольных данных, добавить серверную историю и повторное получение доказательств. Оценки ресурсов и выбор YOLO/Qwen из исследований требуют проверки, прежде чем считать их окончательной архитектурой.

Команды запуска, формат JSON и примеры ручной проверки перечислены в [frontend/README.md](../README.md). Они описывают ожидаемый сценарий, а не подменяют отчёт о фактически проведённых проверках.
